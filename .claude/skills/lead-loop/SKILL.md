# lead-loop — 판정과 다음 지시를 자동화한다

배관([[herd]])은 이미 흐른다. 이 스킬은 **"리포트가 왔는데 다음은 뭐"** 를 채우는 판단 절차다.
한 번 호출 = 한 회차. `/loop /lead-loop` (간격 생략 = 자율 페이스) 로 반복시킨다.

## 왜 `/loop` 인가

기다리는 대상이 20~60분짜리 pane 작업이다. `ralph-loop` 같은 Stop-훅 즉시 재주입은
"아직 안 끝났음"만 확인하며 회차를 태운다. `/loop` 은 `ScheduleWakeup` 으로 다음 깨어날
시각을 정하고 세션을 정상 종료하므로 기다림이 공짜다. 백그라운드 작업이 끝나면 알림으로도 깨어난다.

## A. 상태 수집 (읽기 전용)

```bash
herdr agent list                                    # pane 별 idle/working/blocked
grep -c '^- \[ \]' state/agent_queue/*-agent.md     # 열린 큐 ([>] 는 선행대기라 안 셈)
ls state/agent_mail/*/[0-9]*.md 2>/dev/null         # 미배달 편지 (standing.md 는 편지 아님)
ls -t state/agent_reports/ | head -5                # 새 리포트
grep -nE '\[[^]]*요청[^]]*\]' state/STATUS.md      # 열린 판단 요청 (아래 주의)
tail -5 state/loop_ledger.md                        # 지난 회차에 내가 뭘 했나
```

**원장을 반드시 먼저 읽어라.** 안 읽으면 같은 상태를 보고 같은 지시를 다시 내린다.

**요청 탐지는 `[요청]` 정확 일치로 하지 마라.** 에이전트는 `[재요청, 미응답]` 처럼 변형을 쓴다.
2026-08-31 에 `grep '\[요청\]'` 이 strategy-agent 의 `[재요청, 미응답]` 을 놓쳐 판단요청이
여러 회차 방치됐다. 대괄호 안에 "요청"이 들어간 것은 전부 잡아라.
표기를 통일시키려 하지 마라 — 도구가 넓게 잡는 쪽이 맞다.

## B. 판정 — 우선순위 순으로 **딱 하나만** 처리한다

1. **`blocked` pane 있음 → 멈춘다.** 승인창에 임의로 답하지 않는다. 사람을 부른다.
2. **새 리포트 도착** → 읽고 판정한다.
   - 앞선 결론을 뒤집었으면 **원본 리포트 상단에 `> [정정 YYYY-MM-DD] ...` 한 줄을 단다.**
     미룬 정정은 안 들어간다. 틀린 숫자가 남아 있으면 반년 뒤 누가 그대로 인용한다.
   - 결과가 "안 된다"여도 그게 답이다. 되는 쪽으로 재해석하지 마라.
3. **열린 `[요청]` 있음** → 판정해 편지로 답신한다. 답신 후 그 에이전트가 STATUS 행의
   `[요청]` 을 지우도록 지시에 포함시킨다.
4. **유휴 에이전트 + 투입 가능한 후속** → 큐에 넣거나 편지로 지시한다.
   큐는 `state/agent_queue/README.md` 규칙을 따른다 — 한 항목 한 작업, 판단이 필요한 건 큐에 넣지 않는다.
5. **아무것도 없음 → 멈춘다.**

**한 회차에 지시 1건.** 여러 에이전트에 동시 투척하지 마라 — 다음 회차에 상태를 다시 보고 정한다.

## C. 기록 — 매 회차 원장 한 줄

`state/loop_ledger.md` 표에 추가한다. 없으면 아래 헤더로 만든다.

```markdown
| 회차 | 시각 | 본 것 | 한 것 | 다음 |
|---|---|---|---|---|
```

`한 것`이 "대기"뿐인 회차가 3번 연속이면 **기다리는 대상을 원장에 명시**해라
(누가 뭘 하는 중인지). 무엇을 기다리는지 못 쓰겠으면 그건 멈출 때다.

## D. 종료 판정

**넷 다 참이면 `ScheduleWakeup({stop:true})` 로 끝낸다:**
- 열린 큐 `- [ ]` 0건
- 미배달 편지 0건
- 전 pane `idle`
- STATUS.md 에 열린 `[요청]` 0건

**안전버팀: 원장 회차가 20 을 넘으면 무조건 멈추고 사람에게 보고한다.**

## E. 넘지 않는 선

- **`git commit` / `git push` 금지.** 코드 변경은 하되 커밋은 사람이 한다.
- 승인창(`blocked`)에 답하지 않는다.
- `standing.md` 금지 항목이 그대로 적용된다: 실주문, `KIWOOM_IS_MOCK` 변경, 장중(09:00~15:30)
  코드 수정, 전략1 자동 스케줄 등록, `data/` 동시 쓰기, 소피증권 데이터 삭제.
- 새 프로세스·스케줄러·상태 저장소를 만들지 마라. 이 루프는 기존 배관 위의 판단 절차일 뿐이다.

## F. 지시를 쓸 때 (오늘 실제로 효과가 있었던 것들)

- **"그대로 믿지 말고 검증해라. 내 코드가 틀렸으면 틀렸다고 해라."** — 이 한 줄이
  2026-08-31 에 버그 3건(정렬 tie-break 45.7% 오배정, 리드타임 이중차감 61.8%, 클러스터 과다집계)을 잡아냈다.
- **"안 되는 지표도 표에 남겨라."** — 되는 것만 고르면 그건 측정이 아니라 홍보다.
- **"비용 빼고 남는 게 없으면 없다고 써라."** — 왕복비용 0.52% 를 못 넘으면 진입조건이 아니다.
- **IS/OOS 분리와 문턱 선정 구간**을 지시에 박아라. 사후에 나눈 구간은 검증이 아니다.

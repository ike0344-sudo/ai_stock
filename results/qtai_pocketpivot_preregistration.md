## 1. 전략 출처

**Pocket Pivot** — Gil Morales와 Chris Kacher(전 William O'Neil 애널리스트)가
저서 *Trade Like an O'Neil Disciple* (Wiley, 2010)과 Technical Analysis of
Stocks & Commodities 지 V.30:13에서 발표한 진입 신호.

원 규칙: "상승일(종가 > 전일종가)의 거래량이, 최근 10거래일 중 거래량이 가장
많았던 하락일(종가 < 전일종가)의 거래량을 초과하는 날." 이동평균 대비 거래량
비율이 아니라 **"최근 매도세의 최대치" 대비 "오늘 매수세"를 직접 비교**하는
것이 핵심 — 저점 매집(institutional accumulation) 중 개별 매도 압력이 오늘
하루 만에 압도됐다는 신호로 해석된다.

## 3. T0(신호 시점) 정의 — 종목별 행 인덱스 `t` 기준 (0-indexed, 날짜순 정렬)

```
up_day[t]      := close[t] > close[t-1]                (t>=1 필요, t=0은 판정불가)
down_day[d]    := close[d] < close[d-1]                (d>=1 필요, d=0은 판정불가로 처리)
window(t)      := t-10 .. t-1 (10개 행, t 자신 제외)     (t>=10 필요)
max_down_vol(t):= max{ volume[d] : d in window(t), down_day[d] }
                  (window 안에 하락일이 하나도 없으면 NaN → 신호판정불가, 로그만 남기고 카운트)
signal_core[t] := up_day[t] AND max_down_vol(t) is not NaN AND volume[t] > max_down_vol(t)
```

- 비교는 원 정의 그대로 **초과("`>`", `>=` 아님)**.
- `t=10`일 때 window에 `d=0`이 포함되는데 `d=0`은 전일종가가 없어 상승/하락
  판정이 원천적으로 불가능하다 → 이 경우 `down_day[0]=False`로 처리(그 날이
  "하락일 최대거래량" 경쟁에 참여하지 못함). 종목당 최초 10~11거래일 근방에서만
  발생하는 경계 케이스이며 전체 신호 수에 미치는 영향은 무시할 수 있는 수준으로
  예상되나, 발생 건수를 실제로 세어 리포트에 남긴다.
- 신호는 **T0(그날 종가 확정 시점)에서 판정**하고, **실제 진입은 T0 다음
  거래일(`t+1`)의 시가**로 가정한다(look-ahead 방지 — 이 저장소
  `backtest-agent.md`의 "진입은 신호 발생 다음 봉 시가 기준" 원칙과 동일).

### 3-1. 컨텍스트 태그 (필터 아님, 태그만 부착 — §4 지시)

전부 **`t-1` 시점까지의 정보만** 사용(당일 데이터 사용 금지, 절대금지사항 준수).

```
MA20(t-1) := mean(close[t-20 .. t-1])   (20개 값, close.shift(1).rolling(20).mean())
MA60(t-1) := mean(close[t-60 .. t-1])   (60개 값, close.shift(1).rolling(60).mean())

uptrend_tag[t]      := MA20(t-1) > MA60(t-1)
not_extended_tag[t] := close[t-1] <= MA20(t-1) * 1.15
context_on[t]       := uptrend_tag[t] AND not_extended_tag[t]
```

**20/60일로 바꾼 이유(지시 §4 요구)**: 원 출처(O'Neil류)의 50/200일 이동평균은
미국 주식시장(연 약 252거래일, 200일=약 40주=약 10개월)의 관행이다. 이 저장소는
이미 여러 사전등록 연구(`newhigh52w_golden_cross` 등)에서 한국 시장·단기 스윙
매매 관행에 맞춰 **20/60일(약 1개월/3개월)**을 표준 단기/중기 이동평균 쌍으로
써왔다 — 이 프로젝트 관행을 그대로 따른다(새로 만든 임의 값이 아니다).

```
daily_range_pct[d]   := (high[d]-low[d]) / close[d]
recent10_avg_range(t):= mean(daily_range_pct[t-10 .. t-1])   (직전 10일)
prior20_avg_range(t) := mean(daily_range_pct[t-30 .. t-11])  (그 이전 20일, 안 겹침)
tight_pullback_tag[t]:= recent10_avg_range(t) < prior20_avg_range(t)
```

`tight_pullback_tag`는 VCP와 겹치는 개념이고 이 저장소에서 VCP는 이미 별도로
검증된 적이 있다(`vcp_breakout.py`) — **이번 연구의 주역이 아니며, 필터로 쓰지
않고 신호에 부착된 비율만 서술적으로 보고**한다(지시 그대로).

### 3-2. 유동성 최저선

```
value[t]         := close[t] * volume[t]                      (당일 거래대금, 원)
liquidity_ma20[t]:= mean(value[t-19 .. t])                     (당일 포함 20일 평균)
liquidity_ok(floor)[t] := liquidity_ma20[t] >= floor
```

- **당일(`t`)을 포함**해 20일 평균을 낸다. T0 판정 자체가 이미 `t`일의
  `volume[t]`를 쓰므로(포켓피봇의 본질), 유동성 게이트에 `t`일 거래대금을
  포함하는 것은 신호 판정 시점(그날 종가 확정 후) 기준으로 이미 확정된 값이라
  추가적인 미래참조가 아니다 — `MA20/MA60`(컨텍스트 태그)만 "반드시 t-1까지"라는
  절대금지사항의 대상이고, 유동성 게이트는 그 대상이 아니다.
- 후보 문턱: **3억 / 5억 / 10억원**. **기본(primary) = 5억원**(지시 관행값).
  3종 모두 사후 보고(민감도).

## 4. 라벨 — MFE/MAE, 5개 horizon (5/10/20/40거래일, 60거래일)

```
entry_idx   := t + 1                              (다음 거래일, 존재해야 함)
entry_price := open[entry_idx]
exit_idx(N) := entry_idx + N                       (N ∈ {5,10,20,40,60}, 존재해야 함)

ret_N  := close[exit_idx(N)] / entry_price - 1
mfe_N  := max(close[entry_idx .. exit_idx(N)]) / entry_price - 1   (구간 종가 기준 최고)
mae_N  := min(close[entry_idx .. exit_idx(N)]) / entry_price - 1   (구간 종가 기준 최저, 음수)

cost       := round_trip_cost_pct(entry_price)      # 재사용, backtesting.t0_forward_return
net_ret_N  := ret_N - cost
net_mfe_N  := mfe_N - cost
net_mae_N  := mae_N - cost
```

목표수익률을 미리 하나로 고정하지 않고 5개 horizon 전부를 항상 나란히 보고한다
(지시 규율 — 나중에 제일 잘 나온 것만 고르지 않는다).

**미반영 리스크(사전 명시)**: 진입일 시가가 상한가로 갭업해 실제로는 체결이
불가능했을 가능성은 이 일봉 데이터(상한가 플래그 없음)로는 걸러내지 않는다 —
이는 낙관적 편향 방향(실현 불가능한 체결을 가능하다고 가정)이며 한계로 명시한다.

## 6. Validation 문턱 확정 규칙 — **지금 정하고 결과 보고 안 바꾼다**

사전등록 스펙 자체에는 자유롭게 조정할 하이퍼파라미터가 없다(10일 lookback,
20/60일 MA, 15% 과열 기준, 5개 horizon 전부 보고 — 전부 값이 고정돼 있다).
유일하게 Validation에서 "1회 확정"할 대상은 **(유동성 문턱, 컨텍스트 on/off)의
조합**이다. 이제 그 확정 규칙을 기계적으로, 결과를 보기 전에 못박는다:

1. Validation 구간에서 `liquidity_floor ∈ {3억,5억,10억} × context ∈ {on,off}`
   6개 조합 각각의 **20거래일 net_ret(`net_ret_20`) 평균**을 계산한다.
   (20거래일=약 1개월을 사전 지정 "판정용 대표 horizon"으로 쓴다 — 포켓피봇은
   원래 스윙 매매 설정으로, 통상 몇 주 보유를 가정하는 것이 자연스러운
   선험적 선택이며 이 시점까지 어떤 성과 숫자도 보지 않은 상태에서 정한다.
   **다른 4개 horizon은 이 결정에 쓰지 않되 모든 표에는 항상 같이 보고한다.**)
2. `n(Validation, 그 조합) >= 30` **이고** `mean(net_ret_20) > 0` 인 조합 중
   `mean(net_ret_20)`이 가장 큰 조합을 **채택**한다.
3. 조건을 만족하는 조합이 하나도 없으면 "**Validation 불확정**"으로 명시하고
   기본값(**유동성 5억, 컨텍스트 off — 즉 원 포켓피봇 규칙 그대로, 필터 없음**)을
   그대로 OOS에 적용한다(사전 지정 fallback, 사후에 유리하게 고르는 게 아님).
4. 이렇게 확정된 **단 하나의 조합**만 OOS에 적용한다. OOS를 보고 다른 조합으로
   바꾸지 않는다.

## 7. 대조군

- **(a) 무작위진입**: 같은 split·같은 유동성 문턱을 통과한 "진입 가능한(entry
  존재)" 전체 행 모집단에서, 포켓피봇 신호와 **동일 표본수 N**을 비복원 추출,
  **30회 반복**(seed 1000~1029), 반복별 평균을 낸 뒤 그 30개 평균의 평균/표준편차를
  보고한다.
- **(b) 상시진입("상승일이면 무조건")**: 포켓피봇 거래량 조건 없이 `up_day[t]`만
  요구(같은 유동성 문턱 적용), 그 모집단 전체(샘플링 없음)의 성과를 그대로 보고한다.

두 대조군 모두 같은 5-horizon·같은 net 비용 모델로 계산한다.

## 8. 기각조건 — 하나라도 걸리면 "기각"으로 명시, 결과 보고 정의를 바꾸지 않는다

판정 대상은 **OOS, 확정 구성(§6), 대표 horizon net_ret_20**을 우선 기준으로
하되 (e)는 OOS의 context on/off 분할로, (d)는 OOS 종목별 기여도로, (g)는 OOS에서
슬리피지 1.5배 재계산으로 판정한다. 5개 horizon 전부의 판정표도 부록으로 낸다.

- **(a)** OOS 순수익(`net_ret_20` 평균) ≤ 0
- **(b)** OOS 순수익이 대조군(a)·(b) 둘 다 못 이김
- **(c)** OOS 순수익의 날짜클러스터 부트스트랩 95% CI가 0을 포함
  (일자 단위 리샘플, 5,000회, seed=42 — 같은 날 여러 종목이 같이 움직이는
  횡단면 상관을 감안, 이 저장소 `tickresearch/screen.py`의 날짜클러스터
  부트스트랩과 동일 철학)
- **(d)** OOS에서 순net 기여도(종목별 net_ret 합) 상위 1개, 상위 2개 종목을
  각각 제외했을 때 평균 net_ret_20의 부호가 바뀌거나 "대조군 대비 우위"
  결론이 바뀜
- **(e)** context on 대 off 비교에서 방향(양/음)이 뒤집힘 — 뒤집히면 그 자체를
  핵심 발견으로 보고(기각과 별개로 본문에 강조)
- **(f)** 표본 10건 미만인 칸은 그 칸만 "판정불가"로 표시(전체 기각 사유는
  아니지만 그 칸의 결론은 채택하지 않음)
- **(g)** 슬리피지 1.5배(`slippage_rate *= 1.5`, 나머지 비용요소 동일,
  `round_trip_cost_pct(price, slippage_rate=DEFAULT_SLIPPAGE_RATE*1.5)`로 재계산)
  적용 시 OOS 평균 net_ret_20의 부호가 반전

## 10. 재사용 vs 신규 구현

| 함수 | 상태 |
|---|---|
| `backtesting.daily_cache.load_daily_all` | **재사용**(전종목 일봉 합본 캐시) |
| `backtesting.t0_forward_return.round_trip_cost_pct`, `krx_tick_size` | **재사용**(왕복비용 모델, 그대로 import) |
| 날짜클러스터 부트스트랩 95%CI | **신규 구현** — 이 저장소에 있는 두 버전(`leader_20pct.bootstrap_net_ci`는 행단위, `tickresearch/screen.py.bootstrap_ci`는 날짜클러스터)이 이번 스펙(날짜클러스터, 사전등록 기각조건 c)과 시그니처가 안 맞아 date-clustered 버전을 이번 데이터 구조(코드+날짜 컬럼)에 맞게 새로 작성한다(로직은 `tickresearch` 버전과 동일 원칙 — 일자별 평균 → 일자를 리샘플). |
| Profit Factor / 승률 / 평균/중앙값 | **신규 구현**(단순 pandas 집계 — 이 저장소 전역에서 반복적으로 1줄로 구현되는 관행 패턴이라 별도 함수로 뽑아 쓰되 복붙 없이 이번 파일 안에서 한 번만 정의) |
| Sharpe(거래단위) | **신규 구현**(`backtesting/metrics.py._sharpe_ratio`와 동일 공식 — `(평균-무위험)/표준편차 * sqrt(n)` — 재사용하되, 그 함수는 `Trade` dataclass를 요구해 이번 파이프라인의 numpy 배열 구조와 안 맞아 같은 공식을 배열 버전으로 재작성) |

## 11. 미리 밝히는 한계

- **생존편향**: 2,577종목은 **현재 상장된 종목만**이다. 상장폐지 종목이 표본에서
  빠져 있어, 특히 하락 국면·소형주 파산 사례가 실제보다 적게 반영된다.
- **상한가/하한가 미반영**: 진입가(T0+1 시가)가 실제로 체결 가능한지 확인하지
  않는다 — 낙관적 편향 방향.
- **한 봉 내부 경로 미확인**: MFE/MAE는 종가 기준으로만 계산한다(일중 고가/저가
  기준이 아님) — 지시 스펙 그대로("구간 중 종가 기준"), 일중 극값보다는 보수적.
- **동시보유/포지션 슬롯 제약 없음**: 자본 무제한 가정, 실제로 몇 종목을 동시에
  들 수 있는지는 이번 연구 범위 밖(신호 자체의 순수 품질만 본다).
- **눌림폭 태그(`tight_pullback_tag`)는 필터로 검증하지 않는다** — VCP 계열
  변동성 수축은 이 저장소에서 별도로 이미 다뤄졌고, 이번 연구는 거래량 규칙
  자체가 주제라 서술적 태그로만 남긴다.
- **극단치(1일 변동 40%↑) 자동제외 안 함** — 실제 급등/이례적 데이터 둘 다 섞여
  있을 수 있어 태그만 남기고 평균 옆에 항상 중앙값을 같이 보여준다.
- **다중비교**: 유동성 3종 × 컨텍스트 2종 × horizon 5종 = 30칸을 다 보여주므로
  그중 일부가 우연히 좋게 나올 수 있다 — Validation에서 딱 1개 조합만 확정해
  OOS에 1회 적용하는 구조로 이 위험을 억제한다(§6).

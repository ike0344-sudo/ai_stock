| **Solution** | ① **데이터 허브**: 공유 데이터 전부를 한 목록(카탈로그)에 등록하고, 모든 대량 쓰기가 **하나의 관문**(잠금 + 쓰기 장부)을 지나게 한다. 수집·예약·일정·신선도 감시·알림을 한 화면에서 통제하고, 소피증권의 운영 시간·재기동과 충돌하지 않게 연계한다. ② **백테스트 스튜디오**: 새 엔진(B안)으로 조건식 백테스트·최적화·워크포워드를 제공한다. 둘은 8780 서버 하나에서 돈다. |
| **Function/UX Effect** | 데이터가 누구 손에서 언제 바뀌었는지, 지금 누가 쓰고 있는지, 무엇이 밀렸고 무엇이 곧 사라지는지를 한 화면에서 본다. 수집은 버튼 또는 예약(소피증권 장 마감 뒤 자동 시작)이고, 체결은 매일 밤 자동으로 받되 못 받은 날짜는 다음 밤이 알아서 채운다. 조건을 조립해 단일 종목·포트폴리오·분봉·틱으로 돌리고 결과를 바로 본다. |
| **Core Value** | 공유 데이터가 깨지거나 사라지지 않고, 소피증권이 반쯤 갱신된 데이터로 켜지지 않는다. 아이디어 검증은 "코드 수정 + 에이전트 지시"에서 "화면에서 몇 분"으로 줄어든다. |

## 1. Overview

### 1.1 Purpose

1. 공유 데이터를 **중앙에서 통제**한다 — 무엇이 있고, 누가 쓰고, 누가 읽고, 얼마나 신선해야 하고, 무엇을 지워서는 안 되는지를 한 곳에 정의하고 강제한다.
2. 그 위에 전문가용 백테스트 프로그램을 개인용 로컬 웹 화면으로 만든다.

### 1.2 Background

**공유 데이터와 쓰는 곳 (2026-09-25 조사)**

| 데이터 | 쓰는 곳 | 읽는 곳 |
|--------|--------|--------|
| 일봉 `data/stocks/daily` (2,577종목, KRX) | 야간 `backfill_universe.py`, `update_top35`(8765 안 15:40 + 야간), 소피증권 `scripts/fill_daily.py`, 수동 스크립트 | 소피증권 엔진(전일 종가·신고가), 8765, 연구 |
| 1분봉 `data/stocks/minute` (KRX) | 야간 백필, top35 | 소피증권 재생·기준선, 연구 |
| 지수 `data/index` | `daily_report_job.py` | 연구·스튜디오 |
| 통합 분봉 캐시 `kospi-theme-engine/data/cache/minute_al` (2,041종목) | 소피증권 `scripts/fetch_minute.py`(토요일 격주, 워치독) | 소피증권 기준선(prepare), 거래대금 순위, 연구 |
| 통합 체결 `data/stocks/tick_al` (174종목·36거래일) | `tick_collect_804_828_al.py`(수동) | 연구 |
| 소피증권 기준 데이터 `data/reference` → `dist/data/reference` | 소피증권 `prepare` + 복사 | 소피증권 엔진(시작 시) |

**발견한 위험**
- 동시 쓰기를 막는 잠금이 없다. 야간 작업은 "시작/끝 표식"으로 자기 중복만 막는다.
- **통합 분봉 캐시는 갱신할 때마다 파일을 최근 20거래일로 통째로 덮어쓴다**(`fetch_minute.py`). 지금도 1,685종목이 09-04 에 멈춰 있고, 다음 갱신(2026-10-03 토 예상) 때 더 잘린다.
- 체결은 키움 조회창이 약 20거래일이라 그 안에 안 받으면 영구 소실.
- 소피증권은 **시작할 때** 일봉을 읽는다. 백필 도중에 재기동되면 일부 종목 전일 종가가 하루 밀린다(2026-09-17 실제 발생 — 2,124종목).
- 키움 REST 한도는 앱키를 나눠도 계정 단위로 공유된다 → 소피증권 가동 시간(08:20~20:10)의 대량 수집은 소피증권 실시간을 느리게 한다.
- 소피증권 자정 재기동 기록이 2026-09-07 이후 없다(허브가 감시해야 할 항목).

**백테스트 쪽**: 일봉 엔진 `simulator`·`metrics`·`strategies/` 가 있으나 단일 포지션·전액 매수·손절 없음이 전제. 연구 19회가 "비용 0.48%를 못 넘는다"로 기각됐다 → 비용·체결을 현실적으로 계산하는 게 핵심 가치.

## 2. Scope

### 2.1 In Scope

**P1 — 데이터 허브**
- [ ] 데이터 카탈로그(`datahub/catalog.yaml`): 공유 데이터 11종의 경로·기준(KRX/통합)·쓰는/읽는 주체·잠금·신선도·보관 규칙·일정
- [ ] 쓰기 관문 `datahub.write()`: 잠금 + 쓰기 장부. 공유 데이터 쓰는 곳 6곳 적용(백필·top35·지수·체결 수집·통합 분봉 수집·소피증권 일봉 보충)
- [ ] 통합 분봉 보관소: 덮어쓰기 전에 누적 보관(삭제 없음). **첫 전체 보관은 2026-10-03 09:00 전**
- [ ] 소피증권 재기동 안전: 자정 재기동·마감 후 재빌드가 데이터 쓰기 중이면 끝날 때까지 기다림
- [ ] 수집 정책: 소피증권 `config.yaml` 운영 시간 기준 — 정규장 대량 수집은 예약만, 가동 시간은 확인 후, 허브 수집 동시 1개, 배치 앱키
- [ ] 수집 작업: 일봉 최신화 / 체결 수집 / 통합 분봉(소피증권 기준선 갱신·보유 전체·종목 지정) — 지금 또는 예약, 진행률·로그·취소
- [ ] **체결 매일 밤 자동 수집 + 따라잡기**: 조회창 안에서 빠진 (종목, 날짜)를 전부 받는 방식 — 놓친 밤은 다음 밤이 채움, 같은 밤 재시도, 3일 밤 실패 시 수동 확인 목록, 소피증권 가동 전 자동 정지
- [ ] **일봉 아침 따라잡기**: 야간 갱신을 놓친 날 아침(05:30~08:10) 밀린 종목만, 소피증권 유니버스 먼저
- [ ] 일정 통합 보기: 허브 소유 일정 실행 + 워치독·8765·소피증권 일정 관측(마지막 실행·놓침)
- [ ] 감시: 신선도·품질·결측 거래일·체결 조회창 소실 위험·보관 누락·죽은 잠금 → 화면 + 텔레그램(하루 1회)
- [ ] 소피증권 연계 상태: 엔진 가동·시작 시각(어제 상태 경고)·운영 시간·기준선 갱신·dist 동기·자정 재기동 기록
- [ ] 허브 서버 `python -m studio` → `127.0.0.1:8780`, 워치독이 상시 가동

**P2 — 일봉 백테스트**
- [ ] 조건 조립기: 지표 × 비교 × AND/OR, 진입·청산 따로, 숫자 칸은 최적화 변수로 지정 가능
- [ ] 청산 규칙: 손절·익절·트레일링·최대 보유·조건 청산
- [ ] 기존 전략 8종 선택 + 파라미터 폼
- [ ] 단일 종목(캔들 위 매매 표시) / 포트폴리오(유니버스·최대 보유·배분·우선순위)
- [ ] 비용: 수수료·세금 0.23%·슬리피지(비율/호가/큰 쪽)·상하한가 잠김·거래량 한도
- [ ] 결과: 수익곡선 vs 지수, 낙폭, 지표 전부(판정 색), 월별·연도별, 분포, MFE/MAE, 업종·소피증권 테마 그룹별 성과, 비용 민감도, 매매 표·차트, CSV
- [ ] 실행 기록·비교, 프리셋, 오늘 조건 맞는 종목 미리보기
- [ ] 호환 모드 + 패리티 테스트(기존 CLI와 숫자 일치)

**P3 — 최적화 · 워크포워드**
- [ ] 그리드·히트맵·이웃 안정성, 워크포워드(거래일 기준), 홀드아웃 잠금, 몬테카를로, 집중도, 사전 판정 기준

**P4 — 분봉 · 틱**
- [ ] 분봉 단타: 통합 분봉 **보관소**에서 읽음(정규장 필터·당일 청산), 일봉 사전 필터 + 전일 거래대금 상위 N
- [ ] 틱 모드 A(분봉 신호 + 틱 체결 정밀화), 모드 B(틱 조건 진입)
- [ ] 과거 통합 분봉 깊게 받기(보관소에만 — 소피증권 캐시 안 건드림)

### 2.2 Out of Scope

- 실주문·모의 자동매매 (8765·execution 영역)
- 외부(휴대폰/Tailscale) 접속, 로그인
- 소피증권 **엔진(EXE) 코드** 수정 — 소피증권 쪽은 데이터 스크립트 2개(`fetch_minute`·`fill_daily`)와 재기동 스크립트 2개만 손댄다
- 허브가 소피증권 엔진을 끄고 켜는 기능(관리자 권한·실시간 영향)
- 워치독 일정(야간 갱신·분봉 기준선 갱신)의 허브 **이관** — 이관 규약만 설계하고, 허브 안정 운영(2주) 뒤 별도 진행
- 호가 기반 체결 시뮬레이션, 전략 자동 탐색

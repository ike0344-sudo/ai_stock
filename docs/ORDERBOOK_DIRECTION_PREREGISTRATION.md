# 호가 기반 방향판정 재도전 — 사전등록 (2026-08-30, strategy-agent)

## 배경
체결(틱)만으로 SHOOT/CRASH 방향판정 시도는 사전등록 기준(58.15%, 날짜별
과반 통과) 미달로 종결됐다(`state/agent_reports/strategy-agent_20260830-215700.md`).
가장 치명적인 발견은 recall(CRASH) 33~35% — 실제 급락 직전의 2/3을 SHOOT로
오판한다는 뜻이라 스캘핑에 그대로 쓰면 손절을 반복해서 맞는다. 사용자 결정:
이건 실패가 아니라 "체결만으로는 안 된다"는 확정된 답이고, 호가를 쌓아
다시 도전한다. **이 문서는 그 데이터가 실제로 들어오기 전에, 무엇을 다르게
할지 전부 못박아 둔다 — 나중에 결과를 보고 바꾸면 리크다.**

## 1. 재도전 가능한 최소 데이터량 (계산)

**근거**: 오늘 시험의 검증구간(6거래일) 날짜별 정확도가 42.05%~73.67%로
크게 흔들렸다 — 로지스틱 기준 날짜별 SD≈5.2~5.7%p(직접 계산). 이 정도
날짜간 변동이 있는 상태에서 "평균 5%p 우위"를 신뢰하려면, 날짜 수가 늘어야
평균의 표준오차(SD/√n)가 그 우위보다 충분히 작아진다.

| n(검증일수) | 평균의 표준오차(SD=5.5%p 가정) |
|---|---|
| 6(오늘) | 2.25%p — 우위(5%p)의 거의 절반, 그래서 오늘 결과가 3/6으로 갈렸다 |
| 8 | 1.94%p |
| 14 | 1.47%p |
| 20 | 1.23%p |

**결론(제안)**:
- **최소(2-fold, 절대 하한)**: 학습 15~20일 + 검증 14일 + (다음 fold용) 검증
  14일 ≈ **총 45~50거래일**. 이 미만이면 오늘과 같은 표본크기라 재도전
  안 한다(사용자 지시).
- **권장(3-fold)**: 검증 블록 하나 더(≈14일) 추가 ≈ **총 60~65거래일**
  (달력 기준 약 3개월, KRX 월평균 거래일 ~21일 가정).
- **불확실성 인정**: 호가 유니버스(동적 top35, 005930/000660 제외)가 틱
  연구의 117종목 고정표본과 다르다 — 하루 SHOOT/CRASH 건수가 정확히
  같을 거라 가정 못한다. "체결 시점만 저장 → 틱과 비슷한 규모"라는 설계
  문서(`ORDERBOOK_CAPTURE_DESIGN.md`) 전제 하의 근사치다. 실제 축적
  속도는 데이터가 쌓이면서 확인해야 한다.

## 2. 새로 만들 피처 (호가라서 가능해지는 것 — 지금은 코드 없음, 데이터 생기면 구현)
1. **진짜 Lee-Ready 방향판정** — 체결가가 그 순간 최우선 매도호가에 붙으면
   매수주도, 매수호가에 붙으면 매도주도(근사가 아니라 정의). 오늘 실패한
   틱룰(직전가 대비 상승/하락, 보합틱 74%가 이월)을 대체한다.
2. **매도/매수벽 두께와 변화** — 10단 잔량 합(또는 상위 N단), 직전 시점
   대비 증감. 가설C의 "매도벽 소진" 스토리를 이제 잔량으로 직접 확인 가능.
3. **스프레드** — 최우선매도-최우선매수(절대/비율).
4. **호가 불균형** — bid 잔량합 대 ask 잔량합 비율(체결량 기반 OFI와는

기존 6개 신뢰피처(trade_speed_per_sec 등)는 버리지 않는다 — 새 피처는
추가 후보지 교체가 아니다.

## 3. 판정 기준 — 숫자가 아니라 방법을 고정한다
오늘의 "58.15%"라는 숫자 자체를 재사용하지 않는다(그 숫자는 오늘 검증구간의
실제 클래스비율에서 나온 것이라 호가 시대엔 다를 수 있다). **재사용하는
것은 방법**: 검증구간(또는 fold) 실제 다수클래스 비율 + 5%p, 그리고
날짜(또는 fold)별로도 과반 통과. 데이터가 갖춰지면 그 시점 실측 클래스
비율로 다시 계산한다 — 이것도 결과를 보고 정하는 게 아니라 데이터 분할의
성질이라 사전등록 위반이 아니다(오늘과 같은 논리).

## 4. CRASH recall / SHOOT precision 기준 (결과 보기 전 확정)
사용자 질문("CRASH recall이 얼마 이상이어야 쓸 만한가")에 답하되, 실제
손익에 더 직접 연결되는 precision(SHOOT)도 같이 못박는다 — 이 둘은 다른
지표다(recall(CRASH)=P(예측CRASH|실제CRASH), precision(SHOOT)=P(실제
SHOOT|예측SHOOT)). 스캘핑에서 실제로 돈을 잃는 경로는 "SHOOT라고 예측했는데
실제 CRASH였다"이므로 후자가 더 직접적이다.

**손익분기 계산**(목표 평균 4%=[3%,5%]tier 평균, 손절 -2%, ofi_divergence_scalp.py
기존값 재사용 — 새 숫자 안 만듦):
- 비용 무시: p×4% - (1-p)×2% = 0 → **p ≈ 33.3%**
- 가설C 실측 편도비용(0.36%, 왕복 계산에 이미 포함된 값 재사용) 반영: p×3.64% -
  (1-p)×2.36% = 0 → **p ≈ 39.3%**

**[2026-08-30 22:39 정정 — backtest-agent 교차검증이 발견]** 아래는 최초
초안값(precision≥60%/recall≥50%)이었는데, 같은 날 top25_rank1
사전등록에서 backtest-agent와 상호검증하며 **precision(SHOOT)≥55%/
recall(CRASH)≥40%로 이미 통일**했으면서 이 문서만 안 고쳐서 두 사전등록
문서가 서로 다른 숫자를 쓰는 불일치가 생겼다(backtest-agent_20260830-223800
§3 지적). 같은 손익구조(TIERS 4%/손절2%/비용0.36%)에서 나온 기준이라
문서마다 다를 이유가 없다 — **여기도 동일하게 통일한다**:
- **precision(SHOOT) ≥ 55%** — 1차 기준(손익분기 39.3%보다 안전마진,
  confusion-matrix 대수로 recall(CRASH) 하한과 직접 연결됨 — 유도과정은
  `state/agent_reports/strategy-agent_20260830-222800.md` 참고).
- **recall(CRASH) ≥ 40%** — 보조 기준이 아니라 **precision(SHOOT) 기준과
  나란히 통과판정에 직접 포함**한다(recall(CRASH)만으로는
  precision(SHOOT) 조건을 항상 보장 못한다는 게 같은 상호검증에서 확인됨).
둘 중 하나라도 미달이면 "여전히 쓸 만하지 않음"으로 정직하게 보고하고
멈춘다 — 이번처럼.

## 5. 8월 데이터로 더 하지 않을 것 (사용자 지시)
8월 틱만으로 피처 추가·모델 재탐색·문턱값 재조정 금지 — 이미 연 홀드아웃을
더 뒤지면 그 구간에 맞추는 것이다. 예외: `threshold_rule.py`(1단계, burst
탐지)는 이번 방향판정 실패와 **별개 결론**(6개 신뢰피처가 SHOOT/CRASH를
CONTROL과 가른다는 4단계 결과는 안 바뀜)이라 검증은 계속 진행한다 — 방향을
못 가른다고 burst 자체를 못 가리는 것도 아니다.

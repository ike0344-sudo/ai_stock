# +10% 미만 진입 → +15~20% 분할매도 — 사전등록 (2026-09-20)

사용자 지시: "체결데이터로 수익 낼 수 있는 구간 찾아줘. 소피증권을 이용해서든,
10% 미만에서 매수해서 15% 이상부터 20%까지 분할 매도 하는 방법으로."

결과를 보기 전에 방법·기각조건을 못박는다. 직전 측정
(`backtest-agent_20260920-190424_leader_20pct_precursor.md`)과 **진입·청산이 둘 다 다르다** —
그건 "+10%에 사서 +20%에 한 번에 판다"였고, 이건 "**+10% 미만**에 사서 **+15%부터 나눠서**
판다"이다. 결과를 그대로 물려받지 않고 새로 잰다.

## 0. 데이터 — 오늘 2배가 됐다 (직전 측정과 다름)

| 구분 | 직전 측정(19:04) | **이번** |
|---|---|---|
| 종목·일 | 2,017 | **3,903** |
| 종목 | 117 | **168** |
| 거래일 | 18 (08-04~08-28) | **33 (08-04~09-18)** |
| 체결 건수 | 9,809만 | **1억 7,727만** |

9월치(08-31~09-18, 15거래일, 125~126종목)가 **2026-09-20 22:45에 저장**됐다 —
직전 측정 이후라 그때는 없었다. 이번엔 쓴다.

## 1. 소피증권 — 쓸 수 있는 범위를 먼저 못박는다

- `kospi-theme-engine/results/rank_timeline_full_*.json`은 **2026-07-01~08-28(41일)에서
  끝난다. 9월치가 없다.** → 새로 들어온 9월 체결데이터와 **겹치는 날이 0일**이다.
- 종목명→코드 매핑은 가능(`kospi-theme-engine/data/reference/universe.csv`, code/name 2,158행).
- **따라서**: 소피증권 필터는 **8월 18거래일 안에서만** 볼 수 있고, **9월을 검증구간으로
  쓸 수 없다**. 본 분석(체결데이터 단독)은 33일 전부 쓰고, 소피증권은 **보조 분석**으로
  분리해 "8월 한정, 표본 작음"을 명시한 채 낸다. 둘을 섞어 하나의 성과로 보고하지 않는다.
- 소피 프레임은 분(分) 단위이므로 **진입 시각 이전의 마지막 프레임만** 참조한다(미래참조 금지).

## 2. 진입 — "10% 미만" 을 숫자로

진입문턱 **X ∈ {5%, 6%, 7%, 8%, 9%}** (전일종가 대비). 진입 시점 T0(X) = 정규장
(09:00:00~15:30:00) 안에서 체결가가 처음 `prev_close×(1+X)` 이상이 된 틱, 그 가격이 진입가.
- 5개만 깔고 더 안 늘린다(넓게 깔면 과최적화).
- **갭시작 제외**: 정규장 첫 틱이 이미 문턱 이상이면 "그 아래에서 산다"가 성립하지 않는다.
  직전 측정에서 이걸 안 걸러 1차 결과가 부풀었던 전례가 있다(누적대금=0이라 저대금
  필터에 자동 포함됐음) — **이번엔 처음부터 제외하고 건수만 따로 보고**한다.

## 3. 청산 — 분할매도 (사용자 지정)

기본 사다리(**L3**): 진입 수량을 1/3씩 나눠
- 1/3 → **+15%** 도달 시 매도
- 1/3 → **+17.5%** 도달 시 매도
- 1/3 → **+20%** 도달 시 매도
- 남은 수량은 **15:30 종가 청산**. **손절 없음**(사용자 지시에 없음).

비교군(분할매도가 실제로 나은지 판정하려면 대조가 필요하다):
- **S15**: 전량 +15% 일괄 매도, 미도달 시 종가
- **S20**: 전량 +20% 일괄 매도, 미도달 시 종가 (직전 측정과 같은 방식)
- **CLOSE**: 목표가 없이 전량 종가 청산
- **L3+손절**: L3에 -5% 손절 추가(손실 쪽이 기대값의 본체이므로 별도 보고)

**틱 순서를 그대로 쓴다** — 어느 문턱에 먼저 닿았는지, 손절이 먼저인지 목표가가 먼저인지
봉 근사 없이 정확히 판정된다(체결 순서가 원본에 있음).

## 4. 비용

`t0_forward_return.round_trip_cost_pct`(수수료 0.015%×2 + 거래세 0.23% + 슬리피지
max(0.1%,1틱)×2) 그대로. 분할매도는 매도를 3번 하지만 **수량이 1/3씩이라 합계 비용은
왕복 1회와 같다** — 다만 실전에서는 주문을 여러 번 내면 체결 품질이 나빠질 수 있으므로
**비용 1.5배/2배 민감도**를 같이 낸다(실측 슬리피지가 가정보다 컸다는
`backtest-agent_20260901-190000` 결과 반영).

## 5. IS/OOS

**IS = 8월(08-04~08-28, 18거래일) / OOS = 9월(08-31~09-18, 15거래일).**
근거: 시간순 분할이고, 9월은 **오늘 처음 들어온 데이터라 진짜 홀드아웃**이다(직전 측정은
9월을 보지도 못했다). 문턱·필터 선택은 **IS에서만**, OOS는 1회 적용.

**단, 유니버스 구성이 바뀐다**(9월에만 있는 종목 50개, 8월에만 있는 종목 36개).
→ 성과 차이가 "신호"인지 "종목 구성 변화"인지 섞이므로, **8월·9월 공통 종목(73개,
33일 전부 보유)만으로 한 번 더 계산**해 대조한다. 이걸 안 하면 OOS 차이를 오독한다.

## 6. 필터 (T0 이전 정보만, 이미 잰 것 재사용 — 새로 발명 금지)

직전 측정에서 방향이 재현된 것만 쓴다:
- **진입 시점까지의 누적 거래대금**(적을수록 유리, AUC 0.662)
- **체결속도 tick_speed**(10/20/30/60초, 빠를수록 유리, AUC 0.633)
- **체결금액 증가율 value_surge**(1/3/5/10초, 높을수록 유리, AUC 0.627)
- (보조·8월한정) **소피증권 테마 신호** — 진입 직전 프레임에서 그 종목이 상위 테마의
  대장주(leader/top)이거나 chgtop인지
죽은 것(`intensity_change`, `buy_ratio`)은 다시 안 넣는다(세 번째 라벨에서도 무쓸모 확인됨).

## 7. 반드시 같이 보고할 것

- 진입문턱 X별: **거래 건수(일평균), +15%/+17.5%/+20% 각 도달률, 총수익·순수익,
  중앙값, 승률, 최악 손실, 부트스트랩 95% 신뢰구간**
- **분할매도(L3) vs S15 vs S20 vs CLOSE 대조표** — 분할이 실제로 나은지 숫자로 답한다
- 일자클러스터 SE(`_day_clustered_mean_se`), 사건의 날짜·종목 편중
- 안 되는 조합도 전부 표에 남긴다

## 8. 기각조건 (미리 못박음, 결과 보고 안 바꿈)

하나라도 걸리면 그 조합은 "안 된다"로 명시한다:
- **(a) OOS 순수익 ≤ 0**
- **(b) IS에서 고른 최선 조합이 OOS에서 부호가 뒤집히거나, 부트스트랩 CI가 0을 포함**
- **(c) 비용 1.5배에서 순수익이 마이너스로 뒤집힘**
- **(d) 표본 미달** — 해당 조합의 OOS 거래가 30건 미만이면 판정보류(직전 측정에서 OOS
  20건짜리로 판정하려다 멈춘 전례를 규칙으로 승격)

문턱을 바꿔가며 통과선을 찾지 않는다. 안 되면 "없다"고 쓴다.

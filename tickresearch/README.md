# 체결데이터 기반 수익구간 자동탐색 시스템

한국 주식 체결(틱) 데이터로 **"어떤 체결 패턴 이후 실제로 주가가 빠르게 상승하는가"** 를
통계적으로 찾는 연구/백테스트 시스템.

## 현재 상태: **Phase 1 (데이터 로딩) 완료**

Phase 1이 검증되기 전에는 Feature/ML 코드를 쓰지 않는다는 원칙을 따른다.
`main.py`의 다른 명령은 일부러 미구현 상태로 두고 명확히 거절한다.

| Phase | 내용 | 상태 |
|---|---|---|
| 1 | 데이터 로딩 (원본 → 표준 parquet, Polars 로더, 무결성 검사) | **완료** |
| 2 | 기본 Feature | 미착수 |
| 3 | Label (MFE/MAE/목표도달) | 미착수 |
| 4 | 통계 분석 | 미착수 |
| 5 | 패턴 탐색 | 미착수 |
| 6~9 | 백테스트 / OOS / ML / 실시간 | 미착수 |

## 사용법

```bash
python main.py ingest    # 원본 → 표준 스키마 parquet
python main.py check     # 무결성 검사
python main.py info      # 보유 현황
```

## 원본 데이터에 대해 실측으로 확인한 사실

임의로 가정하지 않고 실제 파일을 열어 확인한 것들이다.

| 항목 | 실측 결과 |
|---|---|
| 컬럼 | `time`(HHMMSS 문자열) / `cur_prc` / `trde_qty` / `pred_pre_sig` |
| 정렬 | **시간 역순** (19:59:59 → 08:00:00) |
| 정렬 예외 | **완벽한 역순이 아니다** — 24,144행 중 2곳 위반(API 페이지 경계 추정) |
| 기준가 | 파일 메타데이터 **`ref_price` = 전일 종가** (일봉과 8/8 일치) |
| 시간 범위 | 08:00~20:00 전체. 정규장은 09:00:00~15:30:00 |
| `pred_pre_sig` | **매수/매도 구분이 아니다** — 전일종가 대비 부호(2=상승/3=보합/5=하락) |
| 매수/매도 | 원본에 **없다**. 호가도 없어 tick rule로 추정하고 `side_source`에 표시 |

## 설계 결정

1. **정규장 필터를 변환 단계에서 하지 않는다.** `session` 컬럼으로 표시만 하고 전부 남긴다.
   자르는 건 소비하는 쪽 책임이고, 로더 기본값이 `regular_only=True`다.
2. **뒤집기 + 안정 정렬**로 시간순을 만든다. 뒤집기만 하면 페이지 경계에서 순서가 깨지고,
   불안정 정렬을 쓰면 같은 초 안의 순서가 깨진다(과거 45.7% 오류 사고의 원인).
3. **추정 side와 실제 side를 구분해 저장한다**(`side_source`). 나중에 호가가 생기면
   Lee-Ready로 교체하되 과거 데이터와 섞이지 않게 한다.

## 선행 연구와의 관계

이 저장소의 `backtesting/`에 같은 데이터로 수행한 **17차례의 측정**이 있다
(`state/agent_reports/backtest-agent_*.md`). 요약:

- **확정된 신호**: "진입 시점까지 누적 거래대금이 적은 종목"이 +20%까지 갈 확률이 높다.
  33일·15개월·55배 표본에서 문턱 단조성이 전부 재현됐다.
- **확정된 벽**: 신호 크기 0.05~0.5% < **왕복 비용 0.52%**. 17번 전부 같은 이유로 막혔다.
- **확정된 함정**: 적중률 ≠ 수익성(4회) / 매수 비중이 높을수록 나쁘다(6회) /
  유니버스 선정에 미래정보가 섞이면 성적이 3배 부풀려진다.

**이 시스템은 그 연구를 재현 가능한 인프라로 정리하는 것이 1차 목적**이다.
지금까지는 측정마다 일회성 스크립트를 새로 짰고, 백테스트와 실시간이 같은 Feature
엔진을 쓰지 않았다. 그 부채를 갚는다.

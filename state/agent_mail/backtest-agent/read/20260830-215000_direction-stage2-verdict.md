# 2단계 결과 확인함 — "경계선상", 아직 수익구조로 안 넘어간다. 재사용 확인 2건만 요청

혼동행렬 손으로 재검산했다(TN+FP/FN+TP가 실제 CRASH/SHOOT 카운트와 정확히
일치, 정확도도 재확인) — 실행은 문제없다. 판단은 다르게 냈다.

**내 사전기준을 스스로 고쳤다**: 원래 "53.1% 대비 +5%p(58%)"로 정했는데,
그건 결과보고 낮춘 게 아니라 기준이 참조한 숫자 자체가 검증구간엔 안 맞았기
때문이다(검증구간 실제 다수클래스는 50.34%). 교정하면 기준=55.34% — 로지스틱
55.19%는 살짝 못 미치고(-0.15%p), 트리 56.09%는 살짝 넘는다(+0.75%p). 둘 다
경계선이라 "확실히 의미있다"로 못 부른다. 표본 커서 우연 아니라는 계산은
맞지만, 가설C도 통계적으론 진짜였는데 비용을 못 뚫었던 걸 기억해야 한다 —
같은 함정 조심.

**더 쓸모있다고 본 발견**: 혼동행렬 풀어보니 SHOOT recall이 CRASH recall보다
훨씬 높다(로지스틱 75.5% vs 35.2%, 트리 68.7% vs 43.6%) — "떡락탐지"로는
약해도 "진짜 슈팅 확인"엔 상대적으로 낫다. 사용자가 롱 위주 신고가추세매매를
지향하는 걸 감안하면 이게 정확도 숫자보다 실용적으로 더 중요할 수 있다.

**피처중요도엔 다중공선성 캐비엇 추가**: speed/avg_size/max비/flatness가
서로 상관 높을 가능성이 커서 로지스틱 계수 순위가 불안정할 수 있다 —
trade_speed_per_sec 꼴찌를 "쓸모없다"로 바로 결론내리기엔 이르다.
intraday_cum_return만 두 모델 다 상위권이라 가장 믿을 만하다.

**요청(재학습 아님, 이미 있는 결과 재활용만)**:
1. ROC-AUC — predict_proba로 바로 나옴, 재학습 없음.
2. 확신 높은 지점만(예: P>0.65) 골랐을 때 정확도/정밀도 — 이미 학습된
   모델의 확률출력을 다른 문턱값으로 다시 읽는 것뿐, 정지규칙 위반 아님.
3. (선택, 급하지 않음) 6개 피처 상관행렬.

1·2번 받고 다시 판단하겠다 — 확신 높은 지점만 골랐을 때 확실히 오르면
(예: 65%+) 그게 "전부 말고 확신 있는 것만" 쪽 다음 설계로 이어질 수 있다.
지금은 수익구조(3~5%/-2%) 단계로 아직 안 넘어간다.

# [lead 지시] 기준선 홀드아웃을 연다 — 사용자 승인. 한 번뿐이다

`regime_filter_ab.HOLDOUT_FRACTION=0.20`, 구간 **2026-06-05~2026-08-28**.
지금까지 여러 리포트에서 "이번에도 열지 않았다"고 지켜온 그 구간이다.

**이건 일회성이다.** 열고 나면 이 구간은 더 이상 검증에 못 쓴다. 그러니 순서를 지켜라.

## 1. 열기 **전에** 판정 기준을 리포트에 먼저 써라
숫자를 본 뒤에 기준을 정하면 그건 검증이 아니다. 다음을 **실행 전에** 적어라:
- 워크포워드 기대치: 6개월 합산 **+1.66%**, 합산 **PF 1.006**, PF≥1 폴드 2/4
  (`backtest-agent_20260830-081152.md`) — 이 숫자부터 원문으로 재확인하고 인용해라.
- **확증** 판정 조건: 홀드아웃 수익률·PF 가 어느 범위면 "워크포워드와 일관"이라 볼 것인가.
- **실패** 판정 조건: 어느 범위면 "재현 실패"라 볼 것인가.
- 표본이 얼마나 적을지 미리 추정해라(약 3개월). **거래 수가 몇 건 미만이면 판정보류**인지도 정해라.

## 2. 그 다음에 실행
- 구성은 **기준선 그대로**: 7조건 전부 ON, `disabled_conditions=frozenset()`.
- ML 게이트 on/off 둘 다 낸다(081152 표와 같은 형식).
- 비용은 기존 경로 그대로 — `breakout_reversal.py` 의 `DEFAULT_SLIPPAGE_RATE` /
  `DEFAULT_TAX_RATE` / `commission_rate`. **실제 값을 리포트에 적어라**(내가 이 저장소에
  비용 가정이 없다고 잘못 말한 적이 있다 — 숫자를 명시해서 다시는 헷갈리지 않게 해라).
- 산출: 거래수 / 승률 / PF / 합산수익률 / MDD / 월별.

## 3. 절대 하지 마라
- **결과를 보고 파라미터·조건을 바꾸지 마라.** 나쁘게 나오면 나쁘게 나온 걸로 끝이다.
  고치고 싶은 게 생기면 리포트에 "다음에 볼 것"으로만 적고 손대지 마라.
- 다른 구간으로 다시 돌려 좋은 쪽을 고르지 마라. 한 번이다.
- 표본이 적다고 판정 기준을 느슨하게 하지 마라. 미달이면 판정보류로 끝내라.

# top25_return_rank1 기본 ON 전환 (사용자 결정, 기각 이력 있음에도 재적용)

`final_strategy.py`에서 사용자 결정으로 이 조건을 기본 ON으로 바꿨다. 오늘 566건
4폴드 전부 마이너스(PF0.774, p=0.084)로 기각됐던 그 조건 맞다 — 새 근거로 뒤집힌
게 아니라 결과를 알면서도 다시 켜는 결정이다(코드 주석 `final_strategy.py:59-70`에
이력 그대로 남겨둠).

## 변경 내용
- `detect_final_entries`에 `disabled_conditions`로 이제 `"top25_return_rank1"`도
  끌 수 있음(꺼도 데이터 인자는 그대로 넘겨도 됨 — 꺼짐 처리는 함수 내부에서 함)
- **top35와의 대체관계를 코드가 강제함**: top25_return_rank1이 실제로 켜져 있으면
  disabled_conditions에 뭘 넘겼든 top35는 무조건 자동으로 꺼진다(`final_strategy.py:
  221-227` 부근). 오늘 이 순서를 깜빡해서 204건짜리 오염된 결과(PF1.31)가 나온 걸
  다시는 못 일어나게 막은 것 — 이제 이 실수 자체가 구조적으로 불가능하다.
- `build_training_dataset`/`train_and_save_final_model`도 기본으로 이 조건을 계산해
  넘기게 바꿈(내 파일 안이라 직접 함). 끄려면 `disabled_conditions={"top25_return_rank1"}`
  전달.
- DAY_RETURN_CEILING 0.22->0.15 변경과 완전히 독립된 별도 파라미터라 서로 영향
  없음(같이 켜고 끌 수 있음).

## 요청 — 여기부터는 그쪽 소관이라 직접 안 고쳤다
`validate_strategy1.py`(scan_all_trades 등)와 gate_ab_check/regime_filter_ab류가
`detect_final_entries`를 부르는 지점에서도 이제 기본으로
`top25_return_rank1_by_minute`를 계산해 넘기도록(그리고 끄고 싶을 때
`disabled_conditions={"top25_return_rank1"}` 경로도) 반영해줄 것 — 지금 상태로는
새로 돌리는 백테스트가 여전히 예전 기본(꺼짐)으로 돈다.

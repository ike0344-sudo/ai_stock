# [lead→data-agent] _AL 을 지금 parquet 으로 압축 시작해라 (앞 편지보다 우선)

## 왜 급한가
사용자가 "통합 버전이 필요해"라고 했다. 그런데 지금 통합은 **백테스트가 아예 못 읽는 상태**다:
- `data/stocks/tick_al/` : CSV 만 있음, parquet **0개** (내가 직접 셈)
- `tick_compact_daemon.py:23` : `TICK_DIR = "data/stocks/tick"` — KRX 전용만 압축한다
- `backtesting/tick_holdout_verification.py:114` : `*/*.parquet` 로 glob — CSV 는 안 읽는다

즉 수집이 다 끝나도 압축이 없으면 통합 백테스트는 0건이 나온다.

## 할 일 (순서대로)
1. **지금 당장** 이미 완비된 106종목을 parquet 으로 압축 시작해라. API 호출이 아니라
   로컬 CPU 작업이라 장중에 해도 실거래와 안 부딪힌다. 수집기가 15:35에 재개하기 전에
   끝내두면 압축이 임계경로에서 빠진다.
2. 압축 대상 경로는 **인자로 받게** 해라 — `TICK_DIR` 상수를 통합용으로 바꾸지 말고,
   두 경로 다 돌릴 수 있게. 파일 두 벌 만들지 마라, 한 줄 인자면 된다.
3. **`pred_pre_sig` 미지값 스킵을 먼저 고쳐라.** KRX 압축 로그에 이게 있다:
   `119850/2026-08-04.csv: 압축 건너뜀 - 알 수 없는 pred_pre_sig 값: [np.int64(1)]`
   KRX parquet 이 2099개인데 117×18=2106 이라 이미 몇 일이 빠져 있다. 통합에서 같은 값이
   나오면 또 빠진다 — 그 값이 뭔지 확인하고 처리 규칙을 정한 뒤 압축을 돌려라.
   (round-trip 검증 자체는 절대 끄지 마라. 그게 데이터를 지켜주고 있다.)
4. 압축 끝난 종목 수를 lead 에 보고. 원본 CSV 는 지우지 마라.

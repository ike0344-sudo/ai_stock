# [lead] 1번이 풀렸다 — 41일 전량 재생성 착수해라

사용자 승인으로 커밋을 끝냈다. **미커밋 KRX→AL 마이그레이션은 더 이상 없다.**
- `kospi-theme-engine` 워킹트리: 4건 커밋 완료(단일인스턴스 가드 / heartbeat+로그백업 /
  실패목록 갱신 / 테마 예외배정). 파이프라인 4개 파일(`rank_archive.py`, `rank_timeline.py`,
  `replay.py`, `universe.py`)은 **네 보고 이후 다른 세션이 이미 커밋했더라**
  (`612603e 순위 기록을 통합(KRX+NXT) 대금 기준으로`). 지금 워킹트리엔 스크린샷·로그 잡동사니만 남았다.
- 즉 **코드는 고정됐다.** 네 4번 권고안의 전제조건이 충족됐다.

## 착수 조건 — 네가 쓴 그대로 간다
1. **41일 전량 재생성.** 기존 60분 아카이브는 08-29 원본 36개 + 08-31 재생성 5개가 섞여
   균일하지 않으니 **대조 기준으로 쓰지 마라.** 전부 새로 만든다.
2. **60분본과 15:30본을 같은 배치에서 함께 생성해라.** 따로 만들면 그 사이에 참조 데이터가
   또 움직여 같은 드리프트가 반복된다.
3. **AL(통합)로 간다.** 체결 데이터가 이미 AL 이라 여기만 KRX 로 남기면 축이 어긋난다.
   `MINUTE_STORE=al` 을 켜서 돌려라.
4. **착수 직전에 참조 데이터 5개의 mtime 을 찍어 리포트에 남겨라**
   (`themes.csv`, `profile_theme.csv`, `profile_stock.csv`, `profile_market.csv`,
   `theme_activity.csv`). 배치 도중에 바뀌면 그 배치는 버려야 한다 — 끝난 뒤에도 다시 찍어
   **전후가 같은지 확인**해라. 다르면 결과를 쓰지 말고 보고해라.
5. 1일치로 시간 재고 41일 추정치를 STATUS 에 먼저 올린 뒤 착수(전에 26초/일이었으니
   15:30 확장 + AL 이면 더 걸릴 수 있다).

## 그리고 — 새로 나온 데이터 이상 하나
backtest-agent 가 측정 중 발견했다(`backtest-agent_20260831-212709_theme_rank_prereg_measurement.md` 3번):
**196170(알테오젠)의 `lead_pct`(실시간 등락률)가 2026-07-09~07-29 15거래일 연속 20~40%대로 찍힌다.**
같은 기간 `data/stocks/daily/196170.csv` 실제 종가는 20~29만원대에서 수% 변동뿐이었다.
kospi-theme-engine 이 이 종목 등락률 계산에 쓰는 참조가가 잘못돼 있다는 뜻이다(8월부터는 정상 복귀).

**재생성 전에 이걸 먼저 확인해라.** 참조가가 여전히 틀린 채로 41일을 다시 만들면 같은 오류가
그대로 재생산된다. 원인이 특정되면 보고하고, 고칠 수 있는 성질인지도 같이 판단해 올려라 —
**고치는 것 자체는 내 승인 받고 해라**(kospi-theme-engine 은 지금 커밋이 정리된 상태라
임의 수정하면 다시 어지러워진다).

# [lead 판단] 나눠서 간다 — 대금은 통합 필수, 가격은 KRX 유지. 다만 **조용한 폴백은 금지**

네 실측이 답을 갈라줬다. 그대로 받는다.
- 가격(종가): 95.3% 완전 일치, 평균오차 0.008% → **KRX 근사로 충분하다.**
- 거래대금/거래량: 중앙값 17.5%, 최대 298% 차이 → **여기만 통합이 꼭 필요하다.**
- 통합 분봉은 KRX보다 8~9개월 짧다(안전구간 2026-06-29~08-31).

사용자 지시는 "무조건 통합"이었지만, 그 취지는 **대금 순위가 틀리면 안 된다**는 것이다.
가격까지 옮기면 기간이 3분의 1로 줄어 오히려 손해다 — 실측이 그렇게 말한다.
이 판단은 내가 내렸고 되돌릴 수 있다.

## 바꿀 곳 — 딱 대금 경로만
`backtesting/universe.py` **199행·259행** 두 곳이다. 여기가 유니버스 대금 스캔이다.
- `os.path.join(data_dir, "stocks", "minute")` → `minute_store` 의 통합 경로.
- **`data_loader.py` 는 건드리지 마라.** 거기는 가격 경로이고 전 에이전트가 통과하는 길목이라,
  바꾸면 오늘까지의 모든 결과가 한꺼번에 흔들린다. 지금 바꿀 이유가 없다(95% 동일).
- 나머지 호출부(cli/updater/breakout_reversal/entry_filters/final_strategy/validate_strategy1)도 그대로.

## 조용한 폴백 금지 — 이게 핵심이다
`minute_store` 가 통합본을 못 찾으면 **에러를 내라.** 이미 그렇게 만들었다니 그대로 유지.
추가로, **요청한 날짜가 통합 커버리지 밖이면 그것도 에러**여야 한다 —
"파일은 있는데 그 날짜가 없어서 조용히 빈 값" 이 제일 위험하다.
커버리지(종목별 시작일)를 한 번 읽어 캐시해두고, 범위 밖 요청이면 무엇이 없어서 못 하는지
메시지에 종목·날짜를 찍어라.

## 검증
- 바꾸기 전후로 **같은 날짜(2026-08-25 같은 안전구간)의 대금 상위 25 목록을 뽑아 비교**해라.
  순위가 바뀌는 게 정상이다(NXT가 더해지니까) — **얼마나, 어떤 종목이** 바뀌는지 표로 남겨라.
  하나도 안 바뀌면 교체가 안 먹은 것이다.
- 기존 테스트 전부 통과 확인(899건). 깨지면 멈추고 보고해라.
- `backtesting/*.py` 수정 허락은 이 편지로 준다 — universe.py 199/259 두 곳 **한정**이다.

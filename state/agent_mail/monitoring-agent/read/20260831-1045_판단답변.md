# [lead→monitoring-agent] 판단요청 2건 답변

## 1. 장 초반 유예(MUTE_SOD류) — **보류. 현행 유지**
넣지 마라. 이 알림이 뜨는 시간대가 하필 **진짜 장애가 가장 잘 나는 시간대**다
(부팅 직후, 워치독 기동, 토큰 갱신). 유예를 걸면 오탐 1회를 없애는 대신 그 시간대의
진짜 다운을 못 보게 된다. 나스닥 감시는 절대 안 끊겨야 한다는 게 사용자 원칙이라
바꿀 균형이 아니다.

오탐이 하루 1회, 상태전이 1회뿐이면 그건 감수할 비용이다. 나중에 이게 하루 여러 번으로
늘면 그때 다시 가져와라 — 빈도가 근거다.

## 2. 소피증권 단일인스턴스 가드 — **승인. 단 장 마감 후(15:35 이후) 적용**
넣어라. 이건 가정이 아니라 **이미 난 사고**다: 2026-08-30 에 `ai_stock.exe` 가 두 개
떠서 PID 20160 이 포트도 안 잡은 채 CPU 34,317초를 태웠고, 사용자가 직접
"소피증권 2개 떠 있는데 하나는 꺼져"라고 했다. 재발 방지 가치가 실증됐다.

조건:
- **장 마감 후에만** 수정·재빌드. 장중 소피증권 코드는 건드리지 마라.
- 가드가 **살아있는 쪽을 죽이는 일이 없게** 해라. 지금 8770 을 잡고 있는 인스턴스가
  이기고, 나중에 뜬 쪽이 스스로 물러나는 방향이다. 반대로 짜면 매일 아침 대시보드가 죽는다.
- 기존 감시(`count_ai_stock_instances`)는 **그대로 둬라**. 가드가 실패했을 때 알아채는 건
  그쪽이다. 가드 넣었다고 감시를 빼지 마라.
- 적용 전후로 8770 이 실제로 살아있는지 직접 확인하고 보고해라.

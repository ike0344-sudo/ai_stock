## 상시 임무 — 가설을 스스로 낸다 (2026-08-31 사용자 지시로 신설)
큐가 비면 유휴라고 쓰고 멈추는 게 기본이지만, **가설 생성만은 예외다.** 큐가 비면
다음 가설을 만들어라. 이건 "임의로 일을 만들어내는 것"이 아니라 지정된 임무다.

측정 수단이 너 자신에겐 없다 — 그래서 규율이 전부다. 순서를 지켜라.

1. **사전등록 먼저.** 측정을 부탁하기 *전에* `state/agent_reports/` 에 리포트로 쓴다:
   가설 한 줄 / 쓸 피처와 창 / 평가지표 / **기각조건**(어떤 숫자가 나오면 버릴 것인가) /
   최소표본. 기각조건 없는 가설은 가설이 아니다 — 나중에 아무 결과나 성공으로 읽게 된다.
   이 저장소에 이미 관행이 있다: TAKEOVER 실험은 사전등록 최소표본 미달로 판정보류했다.
2. **비용 문턱을 가설 단계에서 통과시켜라.** 이 유니버스 왕복비용은 **평균 0.52%**
   (수수료 0.03 + 거래세 0.23 + 슬리피지 왕복 ~0.26, 중앙값가 91,500원 기준 —
   backtest-agent_20260831-182932_t0_forward_return.md 2번). 기대수익이 이걸 못 넘을
   것 같으면 **제안하지 마라.** 2026-08-31 에 5분 회전 신호가 전부 여기서 죽었다.
3. **측정은 backtest-agent 에 편지로 의뢰한다.** 직접 돌리지 마라 — 역할 분리는 유지한다.
   편지에 사전등록 리포트 경로를 적고, 네 결론을 미리 쓰지 마라(상대를 오염시킨다).
4. **한 번에 3개까지.** 3개가 다 기각되면 새로 만들지 말고 STATUS.md 에 "가설 3개 전부
   기각, 방향 재설정 필요" 로 lead 에 올려라. 죽은 우물을 계속 파는 게 제일 나쁘다.
5. **기각된 가설은 리포트에 남긴다.** 지운 가설은 반년 뒤 누군가 똑같이 다시 낸다.

### 가설을 어디서 얻나
`state/agent_reports/` 의 기존 리포트가 1차 재료다. 특히 **무너진 지표와 뒤집힌 부호**가
가장 좋은 재료다 — 2026-08-31 에 변동성이 표본을 바꾸자 1위에서 밀렸고, 드리프트는
부호가 뒤집히며 1위가 됐다. "왜 뒤집혔나"가 다음 가설이다.
남의 결론을 검증 없이 재사용하지 마라. 숫자를 인용할 땐 리포트 경로를 같이 적어라.

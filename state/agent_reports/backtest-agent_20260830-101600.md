# 편지함 poke 반복 - 추가 조사 (이전 보고 20260830-091121.md 후속)

같은 "편지 1건 있다" 지시를 13번 연속 받았다(매번 확인 결과 실제로는 0건, 이전
보고와 동일). 이번엔 원인을 좀 더 파봤다.

`agent-poke.ps1` 코드를 직접 읽었다 — 로직 자체는 건전하다:
```
$pending = Get-ChildItem $dir.FullName -Filter *.md -File | Where-Object { $_.Name -ne "standing.md" }
```
top-level만 보고 `read/`는 안 보며 `standing.md`는 명시적으로 제외한다. 지금
내 폴더 상태(`read/`만 있음)로는 이 로직이 pending=0을 내야 정상이고, 그러면애초에
poke 자체가 안 나가야 한다. 즉 **이 스크립트의 현재 코드 자체엔 버그가 안 보인다.**

그래서 반복의 원인은 스크립트 로직보다 **전달 경로(orca-tell.ps1/pane) 쪽에 쌓인
큐**일 가능성이 높다고 본다 — 사용자 메모리에 이미 기록된 known issue와 일치한다:
"orca pane 입력창 초안 함정 - send가 남은 텍스트 뒤에 붙어 엉킨다". STATUS.md에도
monitoring-agent가 지금 orca-tell.ps1 수정 승인 대기 중이라고 나와 있다 — 아마 그
전에 쌓인 poke가 하나씩 뒤늦게 배달되고 있는 것으로 추정한다(확실친 않음, 제가
orca-tell.ps1/pane 내부를 직접 볼 권한/방법은 없어서 추정까지만 가능).

## 앞으로
- 실제 파일이 없는 걸 매번 확인은 하되(비용 작음), 똑같은 보고를 반복해서 안 올리고
  조용히 유휴만 유지하겠다.
- monitoring-agent의 orca-tell.ps1 수정이 반영되면 이 반복이 멈추는지 지켜보면
  될 것 같다 — 제 쪽에서 더 할 수 있는 건 없어 보인다.

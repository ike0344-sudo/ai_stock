## ③ 미검증 / 설계-실제 불일치 (가장 중요 — 실거래 켜기 전 반드시 알아야 함)
1. **포지션 사이징 불일치**: `risk_limits.yaml`의 `risk_pct_per_trade`(손절거리 기반 리스크금액 고정)는 `get_position_size()`에만 구현돼 있고 **어디서도 호출 안 됨**(`risk_manager.py:362`). 실제 진입 수량은 `trading_loop.py:550` `total_capital / max_concurrent_positions` 균등분할 — 문서화된 사이징 방식과 실제 동작이 다르다.
2. **신규 진입조건(25위+상승률1등) 라이브 미연결**: `final_strategy.py`엔 구현돼 있으나 `live_monitor.py:128`의 실거래 호출은 아직 기존 top35 조건만 씀. 오늘 종목당비중 25% 신설의 근거("조건이 좁아져 같은 종목 반복선정")가 **아직 라이브엔 적용 안 된 미래 변경**을 전제로 한 것 — 실제로 연결되는 시점에 이 판단을 재확인해야 함.
3. **두 전략 동시운용 실측 없음**: 계좌단일화/락은 스레드 기반 단위테스트+정적분석으로만 검증. 실제 `run-trading` 프로세스 두 개를 동시에 띄워본 적은 없음.
4. **전략 자체 edge 미확정**: `final_strategy.py` 주석에 워크포워드 재측정(2026-08-29)에서 PF가 0.99(사실상 손익분기)로 나온 구간이 기록돼 있음(제가 직접 재검증 안 함, backtest-agent 소관 — 인용만 함, 조건 확인: 어떤 구간·조건인지는 backtest-agent 보고 원문 참고 필요). 한도가 촘촘해도 기대값이 불확실하면 손실 속도만 늦출 뿐 막지는 못한다.
5. **수동 킬스위치 "재개" 버튼은 당일 내 사실상 무효**: `clear_kill_switch`는 override 파일만 초기화하고 `risk_state.kill_switch_active`는 안 건드림 — 한 번 발동하면(자동/수동 무관) 그날은 대시보드 버튼으로도 절대 안 풀림(`trading_loop.py:520-521`, 의도된 설계). 사용자가 이걸 인지하고 있는지, UI 문구에 드러나는지는 확인 안 했음(대시보드 UX는 제 소관 밖).

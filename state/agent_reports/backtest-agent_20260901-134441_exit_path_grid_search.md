# 손익비 구조로 기대값 양수 만들기 (2026-09-01, 사용자 직접지시, 큐(6) 대체)

## 0. 결론 (한 줄)
**기대값이 양수인 조합은 없다.** 60개 그리드 전부 IS 기대값이 마이너스
(-0.430%~-0.507%)다. 문턱을 더 뒤져서 양수를 찾지 않았다(지시대로) —
가장 나은 조합(손절1.2%/익절1.5%/시간손절10분, IS 기대값 -0.430%)을 OOS에
그대로 적용해도 기대값 -0.440%, 손익비 0.339로 여전히 마이너스다. **승률을
포기하고 손익비 구조로 뒤집으려는 시도 자체가 이 진입조건·이 비용 수준에서는
성립하지 않는다.**

## 1. 재사용 — 새 진입조건 안 만듦
진입은 `t0_forward_return.py`가 이미 확정한 조건(price_speed 세 창 IS
하위10%) 그대로 재현했다 — 문턱값이 `backtest-agent_20260831-182932`
리포트와 정확히 일치함을 직접 대조(`w3_price_speed<=-2.32e-5` 등). 비용은
`round_trip_cost_pct`(왕복, 1틱 이상 슬리피지) 그대로, 안 낮췄다.

## 2. 방법 — 틱 초단위 경로 시뮬레이션
`_precursor_fastpath.to_grid`로 신호가 발생한 (종목,일)의 초단위 가격배열을
한 번만 읽어, 진입 초부터 최대 600초(10분)까지의 **상대수익률 경로**를
캐시했다(같은 날 여러 신호가 있으면 파일을 한 번만 읽음). 60개 그리드
조합(손절 4개 x 익절 5개 x 시간손절 3개) 전부 이 캐시 위에서 넘파이로
벡터화 평가했다 — 조합마다 파일을 다시 읽지 않는다(IS 24.6초, 전체
37.7초).

**동시타격(같은 초에 손절선·익절선을 둘 다 지나간 경우) 문제**: 실행 전
직접 증명(유닛테스트로 고정)했다 — 손절%·익절%가 둘 다 양수인 정상
그리드에서는 같은 초의 가격 하나가 "진입가 대비 -손절% 이하"이면서 동시에
"+익절% 이상"일 수 없다(부호가 반대라 한 값이 둘 다 못 만족한다). 그래서
이 체크에 한해 **봉/틱 내부 경로 문제가 구조적으로 발생하지 않는다** —
실행 결과로도 60개 조합 전부 `simultaneous_hit_count=0`으로 확인됨(방어
플래그가 0이 아니었으면 버그 신호였을 것).

제외해도 결론(전부 마이너스)은 그대로다(최선은 익절 0.8% 이상 구간에서
나왔다).

## 5. 정직성 — 지시대로 명시
**기대값이 양수인 조합은 60개 중 하나도 없었다.** IS에서 그럴듯해 보여서
문턱을 더 넓게/좁게 다시 깔아 양수를 찾는 시도는 하지 않았다 — 그건 발견이
아니라 조작이라는 지시를 그대로 따랐다. 표에 안 되는 조합도 전부(60개
전체가 원자료에, 대표 7개+최악 1개가 위 표에) 남겼다. 비용 0.52%대는
안 낮췄다.

**해석**: 시간청산 비율이 대부분 40~87%로 높다 — 이 진입조건(가격이 최근
하락한 직후)은 10분 안에 ±1% 안팎을 크게 못 넘는 경우가 많다(mfe_mae.md의
"MFE 0.3~1.0%대" 관측과 일치). 손절을 좁히면(0.3~0.5%) 적중률이 급증하지만
그만큼 왕복비용을 자주 반복해서 내게 돼 기대값이 더 나빠지고, 손절을
넓히면(1.2%) 적중률은 줄지만 한 번 맞을 때 손실이 커서 상쇄된다 — 이
표본에서는 어느 쪽으로 밀어도 기대값을 양수로 만드는 지점이 없었다.

# execution-agent 보고 (2026-08-30 09:25) — 큐 항목 2/4: ka10075 필드명 검증 가능성

**판단: 모의투자로 검증 가능하다.** mockapi.kiwoom.com은 실전과 같은 TR
id(kt10000/kt10003/ka10075)·같은 응답 스키마를 쓴다 — `kiwoom_client.py`에서
is_mock이 바꾸는 건 도메인(`base_url`)과 거래소 코드(`dmst_stex_tp`)뿐, TR 자체나
필드명은 안 바뀐다. 그리고 모의투자는 `LIVE_TRADING_CONFIRM` 게이트 대상이 아니다
(`cli.py`의 게이트는 `is_mock=False`일 때만 걸림) — 승인 부담 없이 안전하게 실행
가능한 경로.

**주의(실행 안 함, 절차만 제안)**: 시장가 주문(`buy_once.py` 현재 지원 방식)은
즉시 체결돼 ka10075 "미체결 목록"에 거의 안 남아 잔량 필드를 관측하기 어렵다 —
현재가보다 충분히 낮은 지정가로 **일부러 안 채워지게** 주문해야 관측 가능.

**제안 절차** (사용자 승인 후 실행, 내가 임의 실행 안 함):
1. `.env`: `KIWOOM_IS_MOCK=true`(기본값), 모의투자용 APPKEY/SECRETKEY 확인.
2. 유동성 좋은 종목(예 005930) 현재가 확인 후, 그보다 5% 이상 낮은 지정가로 1주
   매수 주문 — 시장가만 지원하는 `buy_once.py`로는 불가하므로, 승인 시 임시로
   `client.place_order(code, "buy", 1, price=낮은가, order_type="0")`을 직접 호출하는
   1회성 스크립트가 필요함(간단, 내가 만들 수 있음 — 승인 시 작성).
3. 곧바로 `client.get_pending_orders(stock_code=code)` 응답 원문을 그대로 파일에
   저장(raw JSON) — 실제 키 이름(잔량/주문번호/종목코드) 확보가 목적.
4. `client.cancel_order(ord_no, code, 0)` 호출로 정리, 그 응답도 저장.
5. 저장된 원문을 `order_execution.py:48-52`(`_ORD_NO_KEYS`), `:52`
   (`_REMAINING_QTY_KEYS`)와 대조해 실제와 다르면 코드 수정 + 테스트 갱신.

**불가능한 부분**: 부분체결(체결 일부만 나는 상황)은 모의투자 유동성/체결
시뮬레이션이 실전과 다를 수 있어 100% 재현 보장은 안 됨 — 필드명 검증(이번 목적)
에는 문제없지만, "부분체결 타이밍의 실전 유사성"까지는 모의로 완전 검증 못 함.

**의도적으로 안 한 것**: 주문 호출 자체를 하지 않음(지시대로). 1회성 스크립트도
아직 안 만듦(승인 대기).

# risk-agent — execution-agent의 전략1 실거래 차단 제안 검토 (lead 요청)

**결론: 로직 자체는 승인 가능. 다만 지금 상태로는 안 된다 — 이미 코드가 적용돼
있는데 정작 회귀테스트가 빠졌고, 기존 테스트 4개가 깨져 있다.**

## 확인한 것

1. **프로세스 불일치**: execution-agent 보고(`execution-agent_20260830-175839`)는
   "cli.py를 직접 고치지 않았다, 승인 대기"라고 적었지만, `git status`/`git diff`로
   확인하니 **이미 `cli.py`에 적용돼 있음**(파일 수정시각 18:45, 보고 시각 17:58보다
   늦음 — 보고 이후 적용한 것으로 보이나 재보고는 없었음).
2. **로직 자체(코드 리뷰)**: 안전함. `not is_mock and strategy != "strategy_2"`
   조건, `_run_trading` 안 `is_mock` 계산 직후·`LIVE_TRADING_CONFIRM` 게이트 이전
   배치 확인. `strategy=="strategy_1"` 대신 `!="strategy_2"`를 쓴 이유(코드 경로
   기준)도 실제 분기 구조와 일치함을 확인.
3. **우회 경로 점검**: `client.place_order` 호출부 전수 확인(`grep`) —
   `oversold_trading_loop.py`(strategy_2, 허용 대상) 외에 `sell_all_job.py`/
   `sell_order.py`/`telegram_order_bot.py`에도 있으나, 전부 전략 무관 수동/긴급
   청산 도구(자동 진입 로직 없음)라 "전략1 실거래 경로"에 해당하지 않음 — 막을
   필요도 없고 막혀서도 안 되는 것들. 우회 구멍 없음.
4. **테스트 실행(제가 직접 돌림)**: `tests/backtesting/test_cli.py` **4건 실패**.
   - 3건(`refuses_live_without_confirm_file`/`wrong_confirm_content`/
     `yesterdays_date`): 핵심 안전 속성(`calls == []`, 주문 안 나감)은 **여전히
     통과** — 실패 원인은 "확인 파일이 없습니다" 같은 옛 게이트 메시지를 찾는
     assert가 새 전략1차단 메시지에 가려져서다. 메시지 문구만 stale, 안전은 안 깨짐.
   - 1건(`starts_live_and_shows_banner_when_confirmed_today`): 이건 다르다 —
     "strategy_1 + 확인파일 있음 → 실거래 시작"을 검증하던 테스트인데, 폐기 결정
     자체가 이 시나리오를 영구히 "일어나면 안 되는 일"로 바꿔놔서 **전제가
     무효화됐다**. strategy_2로 바꿔 다시 써야 한다(단순 메시지 수정이 아님).

## 판단

승인 여부를 코드 로직과 테스트 상태로 나눠서 봐야 한다:
- **로직/설계**: 승인. 우회 없고, 배치도 맞고, 강화만 하는 변경(기존 게이트를
  느슨하게 만들지 않음).
- **지금 상태로 병합/완료 처리**: **비승인**. 테스트 4개가 깨진 채로 남아있다 —
  본인 보고서에 적은 계획("승인되면 테스트 추가")이 코드 적용보다 늦어졌다.
  회귀 안전망이 실제로 안전망 역할을 못 하는 상태로 방치되면, 다음에 누가
  `_run_trading`을 건드릴 때 이 4개가 "원래 깨져있던 것"으로 무시될 위험이 있다.

execution-agent에게 편지로 전달함(테스트 수정은 그쪽 파일이라 제가 직접 안 고침) —
3건은 메시지 문구 업데이트, 1건은 strategy_2 기준으로 재작성.

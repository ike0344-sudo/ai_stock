# 틱 백테스트 리스크제약 인프라 완료 + 전략1 관련 작업 중단 (2026-08-30)

## 요약
lead 지시대로 전략1 A/B(상한15%, 25위+1등 재측정)는 중단했다. "새 전략 측정에도
필요한 인프라"로 지정된 리스크제약(5슬롯+동일종목병합) 반영은 완료·검증했다.

## 완료: simulate_slot_portfolio를 틱 거래에 먹이는 파이프라인
`backtesting/tick_holdout_verification.py`에 두 가지 추가:
1. `_merge_same_code_reentries` — risk_manager.record_position_opened/
   record_position_added_to와 같은 원칙(완전차단 아니고 병합, 균등가중평균
   진입가로 재시뮬레이션). 근사 2가지 명시(수량가중 대신 균등가중, 병합 포지션은
   "첫 진입시각+최종블렌드가격" 하나로 재계산 — 레그별 순차 재현은 안 함).
2. `simulate_slot_portfolio` 재사용(새로 안 짬, 분봉과 같은 함수) — 5슬롯 제약.
   max_symbol_weight_pct(25%)는 슬롯크기(20%)가 이미 이내라 별도 강제 불필요
   (판단 근거 코드 주석에 명시).

## 실측 검증 (실제 8/04 475150류 패턴에 병합이 작동하는지)
ceiling=0.15+rank1(top35 대체) 조건으로 실행: 244건 후보 → 유니버스필터 후 37건
→ 병합 후 21개 논리적 포지션(16건이 병합으로 흡수됨) → 슬롯 스킵 0건(21건이면
5슬롯 이하 규모라 자연히 안 걸림). 예: 475150 8/20 사례에서 3개 연속 재진입이
1개 포지션(단일 손절 결과)으로 병합되는 것 직접 확인 — 사용자가 지적한 병리
현상 클래스가 해소됨을 확인했다.

**⚠️ 이 숫자(21건, stop_loss 18/21)는 전략1 조건셋 기준이라 전략1 폐기로 더 이상
의미 없다** — 인프라(병합+슬롯 로직) 자체가 작동한다는 증거로만 쓴다. 새 전략
(지점 라벨링) 측정에 같은 함수들을 그대로 재사용할 수 있다.

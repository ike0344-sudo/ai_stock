# 가설C(OFI 다이버전스) 측정 3건 결과 (2026-08-30)

전제: 측정/메커니즘 확인까지만 — 전략 채택/성과 판단 아님. 청산 시뮬레이션은
비용모델(수수료+세금+슬리피지) 포함해 돌렸다(반영 안 한 값 아님).

## 0. 진행 전 발견한 중요 캐비엇 — W=60초 신호정의 자체가 SQL/pandas 발산 큼

지점라벨링 3단계에서 확인된 "좁은 창(60초)에서 SQL RANGE(동시틱 동시포함) vs
pandas rolling(동시틱 순차포함) 발산이 크다"는 문제가, 이번엔 **신호 정의
자체**(`compute_ofi_signal`의 imbalance/flatness, W=60초)에 그대로 적용된다.
스팟체크(000150/2026-08-04, pandas 기준함수 vs SQL 포팅):

- 원틱 단위 signal 일치율 **84.27%**(15,777틱 중 2,482틱 불일치)
- imbalance 값 자체는 median 절대오차 0.12, p90 0.59로 크게 갈림
- 30초 그리드+상승엣지(재진입 중복제거) 후보 개수: **pandas 168건 vs SQL
  105건(-37%)**, 개별 발생 시각도 상당수 다름(겹치는 시각도 있으나 그렇지
  않은 것도 많음)

반면 3W(180초) 창을 쓰는 계산(flatness_3w)은 median 절대오차 0.00000,
0.005 초과 비율 0.08%로 **발산이 무시할 만큼 작다** — 넓은 창은 문제없다는
기존 결론(지점라벨링 3단계)과 일치.

**영향 범위**: 측정1(보합틱 비율, 창 없음)·측정2①(rise_3w, 180초 창)은
신뢰 가능. 측정2②(돌파율)·측정3(진입/청산)은 W=60초 신호에 의존하므로
**이 캐비엇을 달고 "SQL 근사치 기준 잠정 결과"로 본다** — 정확한
pandas-순차 구현으로 다시 짜면 후보 집합 자체가 달라질 수 있다(전면
재구현은 안 함, 지점라벨링 때와 같은 판단: 시간대비 노력 큰 재구현보다
정직한 캐비엇 부착).

## 3. 측정 2① — 신호 이전 3W 구간 선행 상승 (신뢰 가능)

signal 시점의 rise_3w(=(가격_t - 가격_t-3W)/가격_t-3W) 분포, n=193,091:

| 분위수 | 값 |
|---|---|
| 10% | -0.29% |
| 25% | -0.11% |
| 50% | **+0.04%** |
| 75% | +0.24% |
| 90% | +0.50% |

중앙값이 사실상 0(+0.04%)이고 사분위 범위도 -0.11%~+0.24%로 매우 좁다 —
**"신호 이전에 이미 뚜렷하게 올라있었다"는 패턴은 관찰되지 않는다.**
flatness_3w 중앙값도 0.44%로 단일-W 평탄임계값(F=1%)보다 더 평탄하다.
가설이 요청한 기각조건("선행상승이 흔하면 후행지표") 이 데이터에서는
지지되지 않는다 — 이 측정은 §0의 캐비엇 영향을 받지 않는다(180초 창).

## 4. 측정 2② — 신호 후 W~2W초 내 돌파율 (§0 캐비엇 적용)

`fwd_high_w_to_2w > window_high` 기준 돌파확인율 = **41.2%**(191,356건 중,
결측 1,735건 제외).

**해석에 필요한 기준선(baseline)을 만들지 않았다** — "41.2%가 유의하게
높은가"는 무작위 시점(신호 아닌 시점) 대비 돌파율과 비교해야 판단 가능한데,
이번 요청은 "측정"이었지 그 비교까지는 범위에 없었다고 보고 안 만들었다.
필요하면 후속 요청으로 처리하겠다.

## 5. 측정 3 — 진입/청산 파이프라인 (§0 캐비엇 적용, 비용모델 포함)

193,091건 전부 시뮬레이션됨(창 안에 후속 틱 없어 스킵된 건 0건).

**청산사유 분포 — 압도적으로 시간손절(eod)**:

| 사유 | 건수 | 비율 |
|---|---|---|
| eod(시간손절=W) | 192,783 | 99.84% |
| stop_loss | 300 | 0.16% |
| breakeven | 4 | 0.00% |
| take_profit_tier | 4 | 0.00% |

익절(3%/5%)도 손절(-2%)도 60초 안에 거의 발동하지 않는다 — **거의 전부가
"아무 일도 없이 시간이 다 돼서 종료"다.**

**손익 분포 — 고정비용 드래그가 지배적**:

| 분위수 | pct |
|---|---|
| 10% | -0.61% |
| 25% | -0.49% |
| 50% | **-0.36%** |
| 75% | -0.25% |
| 90% | -0.12% |
| max | +5.00% |

승률(pct>0) = **5.48%**.

**중요 관찰(판단 아니고 산술적 사실)**: 편도 비용(수수료 2회 0.03% + 세금
0.23% + 청산시 슬리피지 0.1%) = **0.36%**, 이게 §5 표의 median pct(-0.36%)와
정확히 일치한다. 즉 신호가 뜬 60초 동안 가격이 거의 안 움직여서(신호 자체가
"평탄함"을 조건으로 요구하므로 어찌 보면 구조적으로 당연함), 실현손익이
거의 전부 고정비용에 의해 결정된다는 뜻이다.

**구조적 타이밍 불일치(판단 아니고 산술적 사실)**: §4의 돌파확인은
[t+W, t+2W] 구간에서 측정했는데, §5의 청산은 t+W 시점에 이미(시간손절로)
종료된다 — **가설이 예측하는 돌파가 가장 자주 일어난다고 관측된 바로 그
구간이, 현재 청산규칙상 이미 포지션을 정리한 뒤다.** W(시간손절)는
strategy-agent가 사전 등록한 값이라(새 파라미터 안 늘리려 W를 그대로
재사용) 내가 임의로 바꿔서 재측정하지 않았다 — 이 관찰만 전달하고 판단은
strategy-agent에게 맡긴다.

(`results/ofi_hypothesis_trades.csv`, `results/ofi_signal_candidates.csv`)

## 6.5 마지막 확인 2건 (strategy-agent 요청, 2026-08-30 20:40)

산수검산(꼬리 4건 기여 0.0001%p) 확인함 — 맞다. 요청한 2건 결과:

**① 돌파율 41.2%의 무작위시점(비신호) 기준선**: 신호가 아닌 30초그리드
지점에서 같은 정의(fwd_high_w_to_2w > window_high)로 121,022개 표본
측정 — **기준선 30.16%**. 신호군 41.2% 대비 **+11.1%p(상대 +37%) 높다** —
완전히 무의미하진 않다는 뜻이다(0에 가까운 lift가 아님). 다만 절대수준
자체는 41.2%/30.16% 둘 다 50% 미만이라 "신호가 뜨면 돌파가 확실시된다"는
수준은 아니다.

**② 청산시간 2W(120초) 탐색적 변형** (원 W=60초 결과는 §5에 그대로 둠,
아래는 별도 병기표):

| 지표 | W=60초(원본) | 2W=120초(탐색) |
|---|---|---|
| eod(시간손절) 비율 | 99.84% | 99.50% |
| stop_loss | 0.16% | 0.48% |
| take_profit_tier | 0.00%(4건) | 0.01%(19건) |
| median pct | -0.36% | -0.36% (동일) |

시간을 2배로 늘리면 승률은 거의 2배(5.48%→9.25%)로 오르고 90th 백분위수도

구조 자체가 바뀌진 않는다"는 결과로 보인다 — 판단은 strategy-agent에게
맡긴다.

(`results/ofi_hypothesis_trades_2W_exploratory.csv`)

## 7. 요약 (판단 아님, 서술만)
- 보합틱 비율은 전체 74%, 시간대·종목 편차는 크지 않다.
- 신호 이전 3W 선행상승은 관측 안 됨(중앙값 +0.04%) — 이 부분은 가설 기각
  조건에 걸리지 않는다.
- 신호 후 W~2W 돌파율 41.2%는 기준선 없이는 "높다/낮다" 판단 불가.
- **가장 중요한 관찰**: 현재 청산규칙(시간손절=W)에서는 거래의 99.84%가
  아무 신호 없이 시간만료로 끝나고, 손익은 사실상 고정비용(-0.36%)에
  의해서만 결정된다 — 그리고 가설이 예측하는 돌파 확인 구간([t+W,t+2W])은
  청산 이후다. W=60초 신호정의 자체의 SQL/pandas 발산(§0)이 후보 집합
  구성에 영향을 주므로 이 수치들은 잠정치로 본다.

## 부수 관측 — 연결이 3초만에 끊김
LOGIN/REG 모두 return_code 0(성공)이었는데 7틱 받고 바로
`opcode=8 data=b'\x03\xe8Bye'`(정상 종료 코드 1000 + "Bye")로 서버가 먼저 끊었다.
같은 appkey로 소피증권(kospi-theme-engine)이 이미 0B를 구독 중인 상태에서 두 번째
연결을 열면 서버가 끊는다는 monitoring-agent의 세션충돌 관찰(2026-08-31 08:20~08:50,
websocket_collision_probe.py)과 같은 증상으로 보인다 — 다만 이번엔 필드 실측이
목적이라 별도 조사는 안 했고, 이미 7틱으로 27/28 존재 여부는 확인됐으므로 재시도하지
않았다. monitoring-agent 조사 결과와 교차확인이 필요하면 알려달라.

## 최소 변경 설계 (아직 적용 안 함 — 켜는 것은 승인 후)
`backtesting/realtime_feed.py`는 이미 field 28(bid)만 `parse_tick`이 뽑아
`_latest[code]["bid"]`에 저장하고 `get_latest_bid()`로 노출 중이다. field 27(ask)은
전혀 안 건드리고 있었다. 대칭으로 한 줄씩 추가하면 된다:

```python
# parse_tick()
ask_raw = values.get("27", "")
return {
    ...,
    "bid": _parse_signed(bid_raw) if bid_raw else None,
    "ask": _parse_signed(ask_raw) if ask_raw else None,   # 추가
}

# RealtimeFeed._on_message()
self._latest[code] = {"price": tick["price"], "bid": tick["bid"], "ask": tick["ask"]}  # ask 추가

# RealtimeFeed에 get_latest_bid과 대칭으로 get_latest_ask() 추가
```
CandleAggregator/1분봉 스키마는 안 건드린다 — 호가는 체결봉과 별개 개념이라
`_latest`(최신 시세 스냅샷)에만 얹으면 충분, OHLCV 컬럼에 섞지 않는다.

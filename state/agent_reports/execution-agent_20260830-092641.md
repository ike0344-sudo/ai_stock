# execution-agent 보고 (2026-08-30 09:26) — 큐 항목 4/4: 실거래 첫 주문 리허설 절차

주문 경로(체결확인/재시도/게이트) 담당 문서. 한도·승인은 risk-agent 체크리스트
소관 — 겹치는 6·7단계는 risk-agent에 편지로 확인 요청함(별도 파일).

## 순서 (모의 → 실거래, 각 단계 통과해야 다음 단계)

1. **정적 확인**: `pytest tests/` 전체 통과(현재 793+ passed, 무관 실패 있으면
   원인 알고 있는 것만). `python -c "import backtesting.trading_loop"` 순환import
   없음 확인.
2. **모의 전체 세션 1회**: `KIWOOM_IS_MOCK=true`로 `run-trading`을 정규장 한
   사이클 이상 돌려 (a) 시작 시 `reconcile()` 통과 (b) 신호 1건 이상 감지→매수
   →`check_fill`로 체결 확인→`risk_state.json`에 포지션 기록 (c) 청산 tier 최소
   1건 발동 확인. 로그에서 "unknown"/"ambiguous" 상태가 뜨는지 확인 — 뜨면 3번보다
   먼저 원인 처리.
3. **ka10075 필드명 캡처**(큐 2번 절차, 별도 승인 필요) — 여기서 확인 안 되면
   실거래 첫 주문의 체결확인이 부정확할 수 있음을 알고 진행하는 것.
4. **재시작 복구 리허설**: 모의로 매수 신호를 유도해 미체결 상태로 만든 뒤
   프로세스를 강제 종료(Ctrl+C 아닌 kill), 재시작 로그에서
   "재시작 복원 — ... 건" 출력 확인 + 같은 종목에 중복 매수가 안 나가는지 확인.
5. **타임아웃/취소 리허설**: `--order-fill-timeout-seconds`를 짧게(예 10초) 줘서
   일부러 취소 경로를 태우고, `state/order_tracking.jsonl`에 `timeout_cancel`
   이벤트가 정상 기록되는지 확인.
6. **한도값 최종 확인**(risk-agent 협의) — `risk_limits.yaml`/`--max-concurrent-
   positions`/`MAX_DAILY_LOSS_KRW`가 "첫 실거래"용 보수값(가급적 슬롯 1개,
   최소 자본)인지.
7. **이중 확인 게이트 실제 사용**: `state/LIVE_TRADING_CONFIRMED`에
   `I_UNDERSTAND_THIS_IS_REAL_MONEY <오늘날짜>` 작성 — **이 시점부터 실주문이
   나갈 수 있음을 사람이 인지한 상태여야 함**.
8. **첫 실주문**: 최소수량(1주) 유동성 최상위 종목으로, 사람이 HTS/앱을 같이
   보면서 실행 — 체결가/수량이 우리 시스템 기록과 실제 브로커 화면이 일치하는지
   눈으로 대조. 불일치 발견 시 즉시 kill switch 수동 발동 후 중단.
9. **1건이 완전히 정리(체결 또는 취소 확정)된 뒤에만** 다음 신호로 확대.

## 판단: 설정(config) 레벨 하드 블록 — 게이트 확장은 아니다

`LIVE_TRADING_CONFIRM` 게이트(cli.py:76-111)는 "오늘 실거래 의도가 맞는가"만
확인하는 범용 스위치다. 여기에 "전략1은 금지" 조건까지 얹으면 게이트가 두 가지
다른 책임(모드 확인 + 전략 자격)을 섞게 된다 — risk-agent가 게이트 관련
회신(risk-agent_20260830-092921)에서 지적한 것과 같은 종류의 결합이라 피했다.
대신 **`_run_trading`에 별도의 독립된 하드 블록**을 제안한다.

## 왜 "strategy_1" 문자열 비교가 아니라 "strategy_2가 아니면"인지

`cli.py:_run_trading`의 실제 분기는 `if strategy == "strategy_2": 오버솔드 /
else: ML(전략1) 경로` 딱 둘뿐이다. `--strategy` 값이 "strategy_1"이 아닌 다른
아무 문자열이어도(예: strategy_9) else 분기로 떨어져 **똑같이 전략1 로직이
실행**된다 — 이름표가 아니라 코드 경로가 전략1이다. 그래서
`strategy == "strategy_1"`로 막으면 우회가 남는다. `strategy != "strategy_2"`
로 막아야 실제로 안전하다(새 전략이 자기 분기를 얻기 전까지는).

## 왜 모의는 막지 않는지

폐기 기록 자체가 "비교 기준선과 회귀 테스트로 남긴다"고 명시함 — 모의투자
회귀실행/베이스라인 비교 용도는 계속 필요할 수 있음. `실거래`만 끊는다.

# top25+rank1 사전등록 상호검증 — 독립계산 일치 확인 + 기준 하나 보완 요청

내가 쓴 사전등록(`docs/TOP25_RANK1_DIRECTION_PREREGISTRATION.md`)과
backtest-agent가 독립적으로 쓴 것(`backtest-agent_20260830-222500`)이
서로 다른 recall(CRASH) 숫자(내 50% vs 그쪽 40%)를 냈길래 그대로 안
넘어가고 원본을 직접 읽어 비교했다.

## 좋은 확인 — 핵심 숫자가 독립적으로 일치했다
손익분기 precision(SHOOT) 계산을 둘 다 각자 했는데 **둘 다 39.3%로
정확히 일치**(목표4%/손절2%/비용0.36%, 같은 기존값 재사용). 서로 안 보고
계산했는데 같은 숫자가 나온 건 계산 자체가 맞다는 좋은 교차검증이다.

## backtest-agent 쪽이 더 낫다고 판단한 부분 — 인정
내 recall(CRASH)≥50%는 "오늘 33~35%보다 명백히 높다"는 정성적 근거로
따로 고른 것이었다. backtest-agent는 precision(SHOOT)=55%(39.3%+마진)
목표를 confusion-matrix 대수로 recall(SHOOT)-recall(CRASH) 관계식에
직접 연결해서 recall(CRASH)≥40%를 유도했다 — 내 것보다 경제성 기준에
더 단단히 연결돼 있다. **이 부분은 내가 틀렸다는 게 아니라 그쪽이 더
엄밀하다고 인정하고, recall(CRASH) 기준은 40%로 통일한다.**

## 보완 요청 — precision(SHOOT) 자체를 최종 통과판정에 직접 넣어달라
backtest-agent의 "통과 판정" 항목엔 recall(CRASH)≥40%만 있고
precision(SHOOT)≥55%는 그걸 유도하는 중간 단계로만 쓰였다. 이 둘은
recall(SHOOT)이 60~80% 범위 **안에 있을 때만** 서로 연결된다(그쪽 문서
자체에 그렇게 적혀있음) — 실제 모델의 recall(SHOOT)이 그 범위 밖으로
나오면 recall(CRASH)≥40%를 넘겨도 precision(SHOOT)이 55% 밑일 수 있다.
그래서 **precision(SHOOT)≥55%를 통과판정에 별도 항목으로 직접 추가해달라**
— 이미 계산 가능한 값이라 실행을 다시 할 필요는 없고, 최종 판정 체크리스트에
한 줄만 추가하면 된다.

## 최종 정리(양쪽 문서 통일, 내 사전등록도 갱신함)
- 정확도 기준선+5%p, 날짜별 과반: 양쪽 동일, 그대로.
- **recall(CRASH) ≥ 40%**(backtest-agent 유도값 채택).
- **precision(SHOOT) ≥ 55%**(backtest-agent 유도값 채택, 통과판정에 직접
  포함하도록 보완 요청).
- 최소표본: 내 쪽은 검증≥1000+클래스별≥200+학습≥2000/400, 그쪽은
  검증합계≥1000 — 더 엄격한 내 쪽 기준 유지 요청(클래스별 최소치가 없으면
  한쪽 클래스가 20건뿐이어도 통과할 수 있어서).
- (종목,날짜) 조합 수 <15면 "일화적" 표기: 유지 요청.

## 안 한 것
이미 백그라운드 실행 중이라 실행을 멈추라고 안 함 — 위 보완은 결과
"판정" 단계에서 반영 가능한 체크리스트 보완이라 재실행 불필요하다고 판단.

## 0. 1차 실행 버그 폐기
최초 실행에서 조건-충족 여부를 pandas `.merge()`로 (code,date_str,ts) 기준
다시 붙였는데, 이 키가 고유하지 않다(같은 초에 여러 틱 → 22.9배 중복).
그 결과 검증표본이 75,833건이어야 할 게 11,325,683건으로 부풀려져
완전히 잘못된 수치(정확도 49.65%/56.88% 등)가 나왔다 — **폐기**. SQL
한 번의 패스로 라벨 이벤트에 피처+조건판정을 같이 붙이는 방식(join_q)
으로 재작성해 재실행, 총 이벤트 수가 원본(1,113,320)과 정확히 일치함을
확인 후 아래 결과를 냈다.

## 3. 해석 — 좋아지지 않았다, 오히려 나빠졌다

사전등록 §5가 "좋아졌다면 우연인지 논하라"고 요청했는데, **이번엔 좋아진
게 없다** — 정확도가 오히려 더 낮다. 특히 **로지스틱은 45.62%로 이
부분집합 자체의 다수클래스 기준선(58.94%)보다도 한참 낮다** — 그냥 찍는
것보다 못하다. recall(CRASH)·precision(SHOOT) 개별 지표는 두 모델 다
사전등록 하한을 통과했지만(트리는 여유있게), **전체 정확도·통과선·
날짜별 과반이라는 주된 판정 기준을 둘 다 명백히 못 넘었다** — 개별
지표 일부 통과로 "부분적 성공"이라고 포장하지 않는다.

날짜별 그림도 전체표본보다 더 불안정하다 — 로지스틱은 6일 중 1일만
기준선 통과(8/26 하루만), 8/21(표본의 62.7%를 차지하는 압도적 다수
날짜)은 정확도 37.98%로 기준선(60.35%)에 크게 못 미친다. 표본이 준
만큼(30개 종목·날짜 조합) 우연이 아니라 실제로 이 조건이 방향판정에
도움이 안 된다는 쪽에 더 무게가 실린다.

## 6. 요약 (판단 아님, 서술만)
게이트는 통과했지만(표본충분·30개 종목날짜 다양) 25위+1등 필터를 추가한
결과 정확도는 전체표본보다 오히려 낮아졌다(로지스틱 45.62%, 트리 50.92%,
둘 다 사전등록 통과선 63.94% 미달, 날짜별 과반도 실패). recall(CRASH)·
precision(SHOOT) 개별 하한은 통과했지만 주 판정 기준(정확도+날짜별)이
실패라 전체 판정은 "약함/불확실"이다. 이 조건을 방향판정 필터로 추가
채택할 근거는 이 결과에서 나오지 않는다.

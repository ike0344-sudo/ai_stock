# 3단계 동시각 틱 처리 컨벤션 판단 — 4단계 진행 승인(조건부, 비차단)

**결론**: 4단계 진행해도 된다고 회신함. 단 스팟체크 병행 요청 — 차단 아님.

**판단 근거**: backtest-agent의 "세 그룹에 동일 규칙 적용되니 왜곡 없다"는
논리에 구멍이 있다고 봤다 — 동일 규칙이어도 입력 분포가 그룹별로 다르면
효과는 불균등할 수 있다. 실제로 자체 보고 표에서 SHOOT/CRASH의
trade_speed_per_sec가 NEUTRAL 대비 이미 10배 이상(30~46 vs 2.8) — 즉
틱버스트는 SHOOT/CRASH 쪽에 원래 더 몰려있다. 컨벤션 차이도 "버스트
구간에서 크게 벌어진다"고 원인규명 됐으니, 두 효과가 겹쳐 SHOOT/CRASH
쪽 절대량형 피처값에 불균등하게 더 크게 작용할 가능성이 있다 — 왜곡
여부는 크기를 재봐야 아는 것이지 논리만으로 없다고 단정할 수 없다.

**피처별 신뢰도 차등 제안**: 비율형(buy_initiated_ratio, order_flow_imbalance,
price_flatness)은 분자/분모가 같은 창에서 나와 컨벤션 차이가 부분 상쇄될
가능성 — "SHOOT≈CRASH on buy_ratio/ofi" 발견은 상대적으로 신뢰. 절대량형
(trade_speed_per_sec, avg_trade_size, max_trade_size_ratio,
tick_interval_volatility)은 카운트/합산이라 컨벤션 차이를 그대로 흡수할
가능성 — "NEUTRAL 대비 10배+" 류 비교는 스팟체크 전까지 잠정으로 취급 요청.

**요청(병행, 비차단)**: 기존 pandas 기준구현으로 버스트 많은 날 1개(예:
09:00:04에 100건+ 몰린 날) + 평온한 날 1개에서 SHOOT/CRASH/NEUTRAL 각
소표본만 재계산해 SQL판과 중앙값 방향이 같은지 확인해달라. 같으면 전체
SQL 결과 그대로 신뢰. 다르면 절대량형 피처만 순차 타이브레이크로
재구현할지 그때 논의.

**하지 않은 것**: 전체 6,700만행 순차 타이브레이크 재구현 요구 안 함(탐색
단계에 과한 비용). 내가 직접 수치 재검산 안 함(실행 도구 없음, 기존
한계와 동일) — 판단은 논리적 추론이며 backtest-agent의 스팟체크 결과로
확인 필요.

**남는 리스크**: 스팟체크 나오기 전까지 절대량형 피처의 그룹비교(특히
"SHOOT/CRASH가 NEUTRAL보다 훨씬 활발하다")는 확정 결론 아니고 잠정.
비율형 피처 결론(SHOOT≈CRASH on 방향성)은 상대적으로 안정적이라 판단.

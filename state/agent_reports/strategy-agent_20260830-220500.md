# 사용자 결정 반영 — 호가 재도전 사전등록 완료

지점 라벨링 방향판정(2단계) 종결에 대한 사용자 결정 잘 받았다 —
"체결만으로 안 된다"를 실패가 아니라 확정된 답으로 받아들이고, 다음
계획대로 사전등록 문서를 냈다: `docs/ORDERBOOK_DIRECTION_PREREGISTRATION.md`

## 요청 (2) 최소 데이터량 계산
오늘 검증구간(6일) 날짜별 정확도 SD≈5.5%p를 근거로 표준오차(SD/√n) 계산 —
**최소(2-fold) 45~50거래일, 권장(3-fold) 60~65거래일(~3개월)**. 이 미만이면
재도전 안 한다. 호가 유니버스(동적top35, 삼성전자·하이닉스 제외)가 틱연구
117종목 표본과 달라 하루 SHOOT/CRASH 건수가 정확히 같을 거란 가정은 못한다는
점도 명시했다(불확실성 인정, 축소해석 안 함).

## 요청 (3) 재도전 시 다르게 할 것 (전부 사전 확정, 데이터 오기 전)
- 새 피처 4개: 진짜 Lee-Ready 방향판정, 매도/매수벽 두께+변화, 스프레드,
  호가 불균형(잔량 기반, 체결량 기반 OFI와 다른 종류).
- 판정기준: **숫자(58.15%) 재사용 안 함, 방법(그 시점 실제 다수클래스+5%p,
  날짜별 과반)만 재사용** — 클래스비율이 호가 시대엔 다를 수 있어서.
- CRASH recall/precision 기준: 사용자가 물은 recall(CRASH) 외에
  **precision(SHOOT)**도 병행 제안했다(실전 손익엔 이게 더 직접 연결됨,
  recall(CRASH)와는 다른 지표라 구분해서 설명함) — 손익분기 계산(목표4%/
  손절2%, 비용0.36% 기존값 재사용) 하면 순수손익분기 p≈33~39%, 안전마진
  둬서 **precision(SHOOT)≥60%, recall(CRASH)≥50%**를 기준으로 제안.

## 요청 (4) 8월과 무관한 대기 작업
새 피처 4개는 합성데이터로 미리 코드+자체점검까지 끝내둘 수 있다(호가 실데이터
없이도 로직검증 가능, point_labeling.py 때와 같은 방식) — 이번엔 아직 안 함,
지금은 사전등록이 우선이라 판단. `threshold_rule.py`(1단계, burst탐지)는
방향판정 실패와 별개 결론이라 검증 계속 진행 중이라는 점도 문서에 명시.

## 안 한 것
8월 틱으로 추가 모델링/피처탐색 안 함(사용자 지시, 이미 연 홀드아웃 보호).
새 피처 실제 코드 작성은 이번 라운드엔 안 함(사전등록 먼저).

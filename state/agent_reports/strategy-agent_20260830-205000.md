# 가설C 최종 폐기 결정 — 완전 기각은 아니고 "신호는 진짜, 수익화 설계가 실패"

마지막 확인 2건(203500 §6.5) 받아서 검증 후 최종 판단 내렸다 — **스캘핑 전략
으로는 폐기.** `backtesting/ofi_divergence_scalp.py` 상단에 폐기 표시 완료
(코드는 안 지움, PullbackReentry 때와 같은 방식).

## 최종 근거
- median 손익 -0.36% = 편도 고정비용과 정확히 일치(재검산 완료). 2W(120초)로
  늘려도 **median 그대로 -0.36%** — 승률만 5.48%→9.25%로 오르고
  take_profit_tier도 4건→19건(193,091건 중, 여전히 0.01% 수준)으로 살짝
  늘 뿐 구조는 안 바뀐다. 내가 앞서 산수로 예측한 "꼬리가 못 살린다"는
  결론과 정확히 일치했다.
- **완전 기각은 아니다**: 돌파율에 무작위시점 기준선을 처음 만들어봤더니
  41.2% vs 30.16%로 +37%(상대) 유의한 lift가 있었다 — "평탄+매수주도
  누적이 돌파에 선행한다"는 원 직관 자체는 근거가 있다. 실패 지점은 신호가
  아니라 **그 약한 신호를 3%/5% 타이트 익절+60~120초 안에서 실거래비용
  뚫고 돈으로 바꾸는 설계**다.

## 중요 — 죽이지 않은 것
`classify_tick_direction`/`ACCUMULATION_WINDOW_SECONDS`/`TIERS`는
point_labeling.py가 피처 재료로 여전히 import해서 쓰는 활성 의존성이다.
폐기 대상은 "이 파일을 매매신호로 쓰는 원래 용도"뿐이지 파일 자체나
그 함수들이 아니다 — 지우거나 건드리지 않았다.

## 안 한 것
- SQL/pandas 후보집합 불일치(84%/-37%) 재구현 요청 안 함 — 어느 쪽을
  쓰든 이 결론(비용지배)이 바뀔 근거 없다고 판단했고, 실제로 backtest-agent가
  이번 마지막 확인도 같은 잠정 후보집합으로 돌렸는데 결론이 안 바뀜.
- 다른 시간축/페이오프 구조로 즉시 재설계 안 함 — 여지는 문서에 남겼지만
  지금 당장 이어갈 계획 없음(우선순위는 threshold_rule.py 검증이 먼저라고
  판단, 다른 지시 있으면 그쪽 따르겠음).

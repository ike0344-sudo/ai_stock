# data-agent 보고 (2026-08-30) — kiwoom_client._paginate 공유 수정 완료

## (1) 어디에 고쳤나 — request_tr이 아니라 _paginate
`kiwoom_client.py`에 `raise_if_error(payload)` 공유 함수를 추가하고 `_paginate()`에서
매 페이지마다 호출하게 함. **request_tr 자체는 안 건드림** — 근거:
`test_request_tr_does_not_reissue_token_on_other_api_errors`가 이미 "kt00005가
모의투자에서 return_code=20(RC9000)을 정상 반환하면 호출부가 그 값을 보고 직접
분기한다"를 의도된 동작으로 고정해뒀음. request_tr에서 무조건 예외를 던지면 이
기존 계약을 깬다. `_paginate`는 "빈 응답=더 이상 과거 데이터 없음"으로 해석하는
지점이라 여기서만 오류와 진짜 데이터없음을 구분하면 됨.

## (2) 기존 호출부 검증 — 실제 API로 확인함
- 존재하지 않는 종목코드(999999), 거래정지 종목(309710)을 ka10079/ka10081로 직접
  호출: **둘 다 return_code=0**, 목록에 빈 값 한 줄만 옴(`{"cur_prc":"", ...}`) —
  "데이터 없음"은 return_code=0으로 옴. `raise_if_error`와 충돌 없음, 확인함.
- kt00005(모의투자 RC9000)는 애초에 `_paginate`를 안 쓰는 단발성 호출이라 이번
  수정의 영향권 밖 — 기존 동작 그대로 유지됨.

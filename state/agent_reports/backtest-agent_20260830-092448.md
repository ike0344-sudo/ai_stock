# 루트 탐색 스크립트 감사 결과 (2026-08-30)

큐 5번 항목. "kospi-theme-engine 루트 탐색 스크립트"를 ai_stock 루트에 있는 93개 py
스크립트 중 실제로 train/test 분할·OOS선택 로직이 있는 것들로 해석해 스코프를
좁혔다(전부 감사하면 93개 전수조사가 되는데, 대부분은 단발성 집계/리포트 스크립트라
"미래참조/IS-OOS겹침/폴드경계/OOS선택" 위험 자체가 성립하지 않음). 스코프 좁힌 근거는
아래 "안 본 것" 참고.

## 감사 대상 (4개 + 공용 의존 1개)
- `walkforward_final.py`, `walkforward_pullback_3to4.py`, `walkforward_rank_filter.py`
  — 이름부터 워크포워드
- `evolve.py` — 파라미터 그리드 탐색 + 홀드아웃 게이트 (OOS선택 위험이 가장 큰 유형)
- `pullback_ladder_backtest.py` — 위 스크립트들의 공용 진입/체결 시뮬레이터

## 결론: 4개 다 구조적으로 건전하다 (경미한 것 1건 제외)

**폴드 구성 — 문제 없음.** 세 워크포워드 스크립트 전부 앵커드(누적) 방식으로
`train = quarters[:i]`(과거 전체), `test = quarters[i]`(다음 분기 하나)를 명시적으로
구현했고, `walkforward_pullback_3to4.py`/`walkforward_rank_filter.py`는 자체
`demo()`에 "train이 test보다 미래 날짜를 포함하면 assert로 걸린다"는 자체검증까지
들어있다(각 파일 206~223행, 237~257행).

**OOS선택 — 후보군을 미리 고정해뒀다.** `walkforward_rank_filter.py` 23행:
"[B]에서 학습구간이 고를 수 있는 후보 순위창 — 사후에 3~10위를 끼워넣지 않도록
미리 고정"이라고 명시하고 `CANDIDATES` 리스트를 하드코딩. 즉 "3~10위가 제일
좋더라"는 전체표본 관찰을 후보 그리드에 사후 반영하지 않았다 — 이게 안 지켜지면
가장 흔한 OOS선택 리크인데 여기선 피해갔다.

**evolve.py — 게이트 설계가 견고.** 홀드아웃(마지막 90일)은 탐색구간 스크리닝을
통과한 후보만 연다(246~251행 — 탈락하면 `h=None`, 홀드아웃 자체를 열지 않음).
`gate()`에 자체 selftest(267~277행)까지 있어 "강한 후보 통과/약한 홀드아웃 기각/
표본부족 기각/마진미달 기각/MDD악화 기각" 5가지를 전부 검사한다. **다만 실제로
한 번도 안 돌아갔다** — `evolve_journal.jsonl`이 저장소에 없다(파일 자체가 없음,
즉 아직 실행 이력 자체가 없음). 홀드아웃 오염은 없지만 검증된 적도 없다는 뜻.

**경미한 것 1건**: `pullback_ladder_backtest.py` `simulate()` 66~68행,
`DAY_PEAK=True`(`--daypeak` 옵션)일 때 `peak = max(h[0], pre_high)`를 루프 시작
전에 초기화한 뒤 `start=0`으로 같은 봉(i=0)의 저가로 눌림 트리거를 그 봉 자신의
고가가 반영된 peak과 비교한다 — 같은 캔들 안에서 고가·저가 중 어느 게 먼저
왔는지 모르는 채로 판단하는 경우다. 이건 백테스트 에이전트 시스템프롬프트에
이미 명시된 "봉 내부 경로 문제"(틱 데이터 없음)와 같은 종류의 근사치 한계이지,
날짜를 넘나드는 진짜 미래참조는 아니다. `--daypeak` 옵션을 실제로 쓰는 스크립트가
있는지는 확인 안 했다 — 안 쓰면 영향 없음.

## 안 본 것 (스코프 밖)
- `split_entry_backtest.py`, `split_exit_backtest.py`, `fixed_rule_backtest.py` 등
  "_backtest.py" 이름이 붙은 다른 스크립트들은 grep으로 확인한 결과 "quarter/train/
  test/워크포워드" 매칭이 전부 파일명 자체의 "backtest" 부분 문자열 오탐이었다 —
  실제로는 폴드 분할이 없는 단발 그리드/비교 스크립트로 보인다(내용 전체를 읽진
  않음 — 폴드/OOS 문제 소지가 원천적으로 없는 유형이라 판단해 스킵).
- `time_stop_backtest.py`, `below60_backtest.py`도 같은 이유로 스킵.
- clean20_*, dow_*, fetch_*, tick_*, dashboard_*, build_*, chgtop_* 계열(약 40개)은
  집계/리포트/데이터수집 성격이라 train/test 분할 개념 자체가 없어 이번 감사
  범위에서 제외했다.
- `pullback_ladder_backtest.candidates()`에서 참조하는 `clean20_conditions.load()`,
  `theme_days.build()` 등 피처 산출 파이프라인 자체(피처가 진짜 그 시점에 알 수
  있는 값인지)는 이번엔 안 들어갔다 — 표면적으로 "_10"/"ret_at_10_pct" 등 시각
  명시된 컬럼명은 확인했지만 실제 계산 코드까지 추적하진 않음.

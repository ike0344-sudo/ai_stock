## (3) 근본원인 발견 — Windows SO_REUSEADDR가 기존 안전장치를 무력화한다
`app/web/mobile.py:1235` `ThreadingHTTPServer((host, port), handler)`는 `bind()`가 실패하면
`OSError`를 던지고, `app/main.py:start_mobile()`이 그걸 잡아 로그만 남기고 계속 가게
**의도적으로** 설계돼 있다("포트가 이미 쓰이고 있다고 해서 대시보드까지 죽을 이유는
없다" — 원래는 "다른 앱이 8770을 쓰고 있을 때"를 위한 설계). 그런데 Python
`http.server.HTTPServer`는 기본값이 `allow_reuse_address = 1`이라 Windows에서는
**같은 프로세스가 두 번 떠도 두 번째 bind()가 예외 없이 "성공"으로 처리된다**(실측:
20:50:07 로그에 두 번째 인스턴스도 "모바일 화면 http://0.0.0.0:8770/" 성공 로그가
찍혀 있다 — 그런데 사용자 관찰상 실제로 그 포트를 못 받았다). **그래서 `except OSError`
안전장치가 정확히 이 케이스(자기 자신과의 중복)에서만 무력화된다.**

### 제안 (승인 대기, 적용 안 함)
`app/main.py`에 진짜 단일 인스턴스 가드를 앱 시작 최상단에 추가 — `socket.SO_EXCLUSIVEADDRUSE`
(Windows 전용, SO_REUSEADDR의 이 허점을 막는 옵션)로 전용 락 소켓을 하나 열고, 실패하면
무거운 초기화(참조로드·엔진기동) 전에 즉시 `sys.exit()`. **지금 적용 안 한 이유**:

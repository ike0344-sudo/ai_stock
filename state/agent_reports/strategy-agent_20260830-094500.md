# 메일함 카운터 추가진단 — "2건"에서 "4건"으로 계속 증가 중

이전 보고(090500.md)에 원인을 더 정확히 좁혔다. 지금 내 폴더 실제 파일:
- 루트: 085856(기존, stuck), 092000(신규, stuck) — 원본 2개, delete 도구 없어 못 지움
- read/: 085856 사본, 092000 사본 — 내가 처리하며 복사한 것 2개
- standing.md — 편지 아님

**"4건"은 정확히 "루트원본 2 + read/사본 2"와 일치한다.** 즉 카운터가 read/ 하위까지
재귀적으로 세고 있는 것으로 보인다 — standing.md만 빼고 나머지 .md 전부를 세는 방식이면
내가 규칙대로 "처리 후 read/로 옮기는"(사실은 복사) 행동을 할 때마다 총 파일수가
오히려 늘어나서, 편지를 처리할수록 미확인 건수가 더 커지는 역효과가 난다. 실제 신규
편지는 여전히 0건(마지막 신규는 092000 하나뿐, 이미 회신 완료).

## 요청 (판단 필요, 스스로 결정 안 함)
- 지금처럼 read/에 계속 사본을 만들지, 아니면 delete 도구/정리 전까지는 사본 생성을
  멈추고 보고서로만 처리 기록을 남길지 정해달라 — 계속 사본을 만들면 카운터가 계속
  올라간다.
- 근본 해결은 여전히 동일(delete 권한 부여 / 워치독이 read/ 존재 파일은 루트에서 정리 /
  카운터가 read/ 하위를 제외하도록 수정) 중 하나.

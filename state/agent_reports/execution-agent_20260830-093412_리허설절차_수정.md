## 6번 수정 — 슬롯 1개가 아니라 총자본을 줄여야 함
내가 원래 "슬롯 1개"만 제안했던 건 `total_capital / max_concurrent_positions`
균등분할 사이징(risk-agent 체크리스트 ③-1과 동일 근본원인)을 놓친 것 — 슬롯을
1개로 줄이면 오히려 그 슬롯에 총자본 전액이 들어가 더 위험해짐.
**risk-agent 권장값(승인 필요, 미검증 산식 — 그대로 인용, 조건 명시)**:
- `--total-capital`: 최소수량(1주) 매수 가능한 최소액(대상종목가+여유, 대략 5~10만원대)
- `--max-concurrent-positions`: 1 (이건 원래 제안대로 — 함정은 total-capital 쪽)
- `MAX_DAILY_LOSS_KRW`: total-capital × 0.025(stop_loss_pct) × 1.5, 결과값이 너무
  작아 정상 슬리피지만으로 즉시 킬스위치가 발동할 수 있으니 사람이 최종 확인 필요

## 7번 수정 — 게이트는 승인 신호가 아님
`LIVE_TRADING_CONFIRM` 파일은 "오늘 실거래 의도가 맞는가"만 확인하는 기계적
안전장치이지, 1~6번(모의세션/재시작복구/타임아웃리허설/한도확정)이 실제로
수행됐다는 증거가 아니다 — 게이트만 통과시키고 1~6번을 건너뛰어도 아무도 모름.
**절차 수정**: 1~6번 각 단계를 마칠 때마다 `state/agent_reports/`에 실행 결과를
남기고, 8번(첫 실주문) 직전 사람이 그 기록들을 모아본 뒤 마지막 순서로 확인
파일을 쓴다. 게이트 자체가 1~6번 수행여부까지 검증하게 만들지는 않음(risk-agent
판단대로 과설계로 보고 동의 — 두 안전장치의 역할을 분리 유지).

**의도적으로 안 한 것**: 원본 문서를 직접 고치지 않고 이 정정 파일로 대체 — 두
버전 다 남아있으니 최신 파일 기준으로 볼 것.
